## 一、视觉定位

### 1.1 一句话美术主张

> **在灵气死去的世界里，用最省的 16 色索引板，画出青苔爬上铜器的那种旧。**

### 1.2 定位说明

| 维度 | 定位 | 反面（禁止） |
|---|---|---|
| 基调 | **末法时代的暗青 + 古铜 + 月白**：整体偏冷、偏灰、低饱和，高饱和只留给灵光与血 | 明亮卡通、糖果色、渐层厚涂 |
| 风格 | 像素风，32×32 瓦片基准，硬边像素、无抗锯齿、无软阴影 | 半写实厚涂、3D 渲染感、模糊滤镜 |
| 氛围 | "仙门衰败"：褪色的幡、生锈的铜、半塌的屋檐、夜里的一点灯火 | 仙气飘飘的明亮天宫、饱满繁华市集 |
| 对比 | 冷底（暗青）压场，暖点（符纸黄、灯火）叙事，灵光青只用于**灵力与阵纹** | 各色乱用、灵气到处发光 |
| 情绪 | 安静、克制、略带衰败的温柔 | 恐怖血腥、刺激夸张 |

### 1.3 视觉三原则

1. **旧而不脏**：做旧靠"褪色 + 铜锈 + 磨损边"，不靠噪点糊图。
2. **省色不省意**：任何一块瓦片只用调色板内颜色，但要能一眼看出"这是茅山的符纸味"还是"这是昆仑的雪线"。
3. **夜色是主角**：本作一半时间在夜里跑，夜间的可读性优先于白天好看。

## 三、素材规格表

### 3.1 通用规格

> **全表硬规则（对所有位图无一例外）**：必须是 **PNG-8 索引色**（`colorType = 3`、`bitDepth = 8`），调色板**严格等于** 16 色板（顺序一致、不多不少），**色板外像素数必须为 0**；索引 0（透明槽）的使用限制见 §2.2 与 §3.3。
> 本表是素材尺寸与体积上限的**唯一定义处**，其他章节只写「见 §3.1」，不复述数字。

| 类型 | 尺寸 | 格式 | 上限 | 备注 |
|---|---|---|---|---|
| 地图瓦片 | **32×32** | PNG-8 索引色瓦片集 + TSX | 单文件 ≤ 512 KB | 无缝可拼；分层拆文件（ground / building / deco）；**禁用索引 0**；由 L0 脚本产出（§4.1） |
| 角色精灵 | **32×48**（步行）、**48×48**（战斗） | PNG-8 索引色图集（网格） | ≤ 1 MB | 透明背景，帧对齐同一画布；源为 `.px.txt` + `.atlas.json`（§4.1 L1） |
| Boss 精灵 | **96×96** | PNG-8 索引色图集 | ≤ 1.5 MB | 出场演出可用放大的 48×48 |
| Boss 立绘 | **96×96**，显示时按**整数倍放大**（2× / 4× / 8×） | PNG-8 索引色 | ≤ 128 KB | 战斗左侧半身像，方形构图、主体偏右，左侧留给血条与状态栏。**为什么不再是 768×1024**：卡带机像素风下写实半身立绘不可得（16 色 + 32px 基准画不出写实层次，硬做只会得到"厚涂缩图"），而本节原本就允许"出场演出可用放大的 48×48"——于是把立绘规格直接收敛成 96×96 索引图、由引擎整数放大显示，与全局像素密度一致，也省掉一张需要单独维护的大图 |
| NPC / 同伴精灵 | 32×48 | PNG-8 索引色图集 | ≤ 512 KB | 与玩家同规格，便于共用锚点 |
| UI 图标 | **32×32**（背包/列表）、**64×64**（详情/技能） | PNG-8 索引色 | ≤ 64 KB | 透明背景，居中，1px 深墨青描边（色值见 §2.1） |
| 场景背景 | **程序化多层视差像素风景（L0）**：单层画布 = 逻辑分辨率，层数 ≤ 5 | PNG-8 索引色 | 单层 ≤ 256 KB | 主菜单、结局、章节标题用；**不做地图背景**；层位移速度在场景内定义，整屏显示由引擎整数放大（§8.6） |
| 战斗特效帧 | **64×64**（技能）、**128×128**（Boss/天劫） | PNG-8 索引色图集 | ≤ 512 KB/技能 | 帧数 8~32，透明背景 |
| 粒子贴图 | **8×8 / 16×16 / 32×32** | PNG-8 索引色单帧 | ≤ 16 KB | 雨滴 2×8、雪花 3×3、火星 3×3 等 |
| 符箓小游戏图层 | 512×512 底图 + 32×32 符纹印章 + 64×64 符笔 | PNG-8 索引色 | ≤ 512 KB 合计 | 分层：纸底 / 符纹 / 笔迹 / 评分高亮 |
| PWA 图标 | 见 §3.2 | PNG-8 索引色 | ≤ 100 KB | 全量入 `public/icons/`；由 L0 脚本按各目标尺寸**重新栅格化**，不放大位图 |

### 3.2 PWA 图标尺寸清单

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `icon-192.png` | 192×192 | PWA `any` purpose |
| `icon-512.png` | 512×512 | PWA 启动图 / 安装弹窗 |
| `icon-192-maskable.png` | 192×192 | Android 自适应图标（内容留在中央 80% 安全区） |
| `icon-512-maskable.png` | 512×512 | Android 启动画面 |
| `apple-touch-icon.png` | 180×180 | iOS 添加到主屏 |
| `favicon-32.png` | 32×32 | 浏览器标签页 |
| `favicon-16.png` | 16×16 | 兼容旧浏览器 |

- 图标主视觉：**镇口残碑 + 一点灵光青**；背景用暗青、描边深墨青（色值见 §2.1）。
- 图标必须是"小尺寸可辨认"的：16×16 下只需看出"一块碑 + 一点青光"。
- 生成方式：L0 脚本按**每个目标尺寸重新栅格化**（几何用整数参数描述），而不是把一张大图缩小或把一张小图拉大——只有重绘才能同时满足 16×16 的可辨认与 512×512 的细节。
- 本清单是平台规定的固定尺寸，**不受 §3.3 第 1 条"8 的倍数"约束**（如 180×180）。

### 3.3 尺寸与格式硬规则

1. **整数像素**：一切像素坐标为整数；瓦片、图标、粒子的宽高必须是 2 的幂或 32 的倍数（8 的倍数可接受）；PWA 图标以 §3.2 的固定清单为准。
2. **禁止放大位图**：32×48 精灵不得直接拉伸到 64×96，需要大图就重新生成。**唯一例外**是 Boss 立绘（§3.1）：96×96 索引图由引擎按**整数倍** `setScale(n)` 显示，不产出放大后的位图文件。
3. **禁止在引擎内做滤镜**：不用模糊、发光、投影等会破坏像素硬边的效果；发光用"多层同心色块 + 低 alpha"手做。
4. **索引色与索引 0**：
   - 所有位图必须 PNG-8 索引色、调色板严格等于 16 色板、**色板外像素 0**（§2.2 的零容忍口径）；明暗层次一律用 **Bayer 4×4 抖动**在 15 个实色之间过渡，不得引入衍生色。
   - **索引 0（透明槽）瓦片禁用**：`render-pixels.mjs` 对 `kind=tile` 直接报错，`check-assets.mjs` 对瓦片内出现索引 0 判错——瓦片只要有一个透明像素，平铺时就会"透底"。
   - **索引 0 精灵 / UI / 图标 / 特效 / 立绘可用**：表示透明背景，逐像素决定，不做"接近透明"的中间 alpha。
5. **单文件上限**（[13-技术架构与工程约定](13-技术架构与工程约定.md) §11）：瓦片集 ≤ 512 KB、精灵图 ≤ 1 MB、音频单文件 ≤ 2 MB；超限必须拆分或重新生成，不允许"靠压缩器补救"。

## 四、素材生产线（L0 ~ L4）

### 4.1 五级来源表

卡带机像素风的生产方式不是"出图 → 修图"，而是「**按参数合成 → 按规则校验**」：能在脚本里算出来的，就不交给模型；能用文本矩阵表达出来的，就不存二进制。素材来源分五级，**优先级从 L0 递减到 L4**——能用 L0 就不用 L1，能用 L1 就不用 L4。**L4 是可选增强，不是必经路径**：整部游戏在完全不使用 AI 的前提下必须可完成（降级方案见 [15-开发路线图与里程碑](15-开发路线图与里程碑.md)）。

| 级别 | 来源 | 手段 | 产出 | 授权 |
|---|---|---|---|---|
| **L0** | 程序化生成 | 脚本按参数合成；图案基于模运算，**构造性无缝** | 瓦片、UI 九宫格 / 条 / 按钮、粒子、PWA 图标、程序化视差背景 | 项目自有（`license: project`） |
| **L1** | 文本矩阵 | `.px.txt`（`@size` / `@anchor` + 索引字符矩阵，格式说明见 `scripts/lib/pixels.mjs`）→ `node scripts/render-pixels.mjs` | 角色 / NPC / 敌人精灵、特效帧、物品与技能图标 | 项目自有 |
| **L2** | PSG 合成 | `.psg.txt` 文本音序 → `node scripts/gen-audio.mjs` | **全部 BGM 与 SFX**（规格见 §10） | 项目自有 |
| **L3** | CC0 补充 | 从 opengameart / freesound / kenney / github 可达的来源人工挑选与整理 | **点阵中文字体**、少量环境采样 | 逐文件核对，**必须登记附录 A.1**（§11.2） |
| **L4** | AI 增强（**可选**） | Retro Diffusion API（`api.retrodiffusion.ai` 实测可达，**需 API key**），或免费端点出草稿后**量化** | 风格探索、批量草稿、手写成本过高的复杂画面 | 见 §11.1，**必须登记附录 A.2** |

**各级的源、命令与落点**：

| 级别 | 源（是否入库） | 生成命令 | 产物落点 | 清单字段 |
|---|---|---|---|---|
| L0 | 无源文件，**脚本即唯一真源** | `node scripts/gen-tiles.mjs` | `src/assets/tilesets/**` | `source: "L0"`、`generator` |
| L1 | `src/assets/pixel/**/*.px.txt`（**入库**） | `node scripts/render-pixels.mjs` | `src/assets/{sprites,ui,vfx}/**` | `source: "L1"`、`sourceFile` / `atlas` |
| L2 | `src/assets/psg/**/*.psg.txt`（**入库**） | `node scripts/gen-audio.mjs` | `src/assets/audio/**` | `source: "L2"`、`sourceFile` |
| L3 | 外部文件，整理后入库 | 无仓库内脚本（人工挑选） | 字体 / 环境采样 | `source: "L3"`、`license`、附录 A.1 |
| L4 | 提示词 + 草稿（草稿**不入库**） | 外部 API，无仓库内脚本 | 量化后的 `.px.txt` 或索引 PNG | `source: "L4"`、附录 A.2 |

- 已落地的是 L0 瓦片生成器与 L1 渲染器（`png.mjs` / `pixels.mjs` 为零依赖内置库）；UI、图标、粒子等 L0 生成器按同一范式补齐，文件名以 `assets.manifest.json` 的 `generator` 字段为准（本表不复述）。
- **粒子两条路都允许**：几何/噪声形态的（雨滴、雪花、火星）走 L0 参数化生成；需要逐像素控制形态的走 L1 的 `.px.txt`（如已入库的 `particle-spirit`）。清单里的 `source` 字段记录实际走的哪条路，两条路都受同一套校验。
- **L2 合成器未落地前**，音频条目在清单里保持 `status: planned`——素材状态以清单为唯一定义处。
- 全部产出必须在 `src/assets/assets.manifest.json` 登记后才能被 `src/` 引用（目录见 §5.1）。

**L4 的网络实测事实**（这就是它只能当"可选增强"的原因）：

| 端点 | 实测结果 | 结论 |
|---|---|---|
| `api.retrodiffusion.ai` | 可达，**需要 API key** | 目前唯一可用的 AI 出图路线 |
| `image.pollinations.ai` | 可达，但返回 **JPEG**，**不保证精确尺寸、不保证无缝** | **只能出草稿**；必须量化 + 重排尺寸后才可能入库 |
| `huggingface.co` | **本环境不可达** | 拿不到模型权重 |
| `api.openai.com` | **本环境不可达** | 云端模型路线不可用 |

> 结论：**"在本地跑一个像素模型"这条路线不可行**（权重下不到），依赖 HuggingFace 的免费端点同理。L4 的现实形态只有两种——付费 API 出图并量化，或免费端点出 JPEG 草稿后**人工/脚本量化成 `.px.txt`**。

### 4.2 L4 提示词模板（可选增强）

> 仅当走 L4（§4.1）时使用，**不构成素材来源分级的一部分**：出图一律视为**草稿**，必须经 §4.3 的量化与校验才能入库。能用 L0 / L1 表达的素材，不要用本节。

**共同约束词**（每条提示词都必须带括号里的三件套）：`统一调色板（16 色，见 §2.1）`、`像素风`、`32x32 无缝瓦片`（瓦片类）或 `透明背景`（精灵 / 图标类）。

| # | 模型 | 提示词 |

### 4.3 后处理与校验

**规则变了**：旧版要求"AI 出图后逐张人工后期"。在 L0 / L1 / L2 路线下，**这些步骤大多由脚本自动保证**——源就是参数与字符矩阵，不存在"出图后再修"的环节；**只剩审美判定需要人工**。

| 步骤 | L0 / L1 / L2 下由谁保证 | 还需要人工吗 |
|---|---|---|
| 1 取色归一 | 编码器只接受索引：`encodeIndexedPng` 输出的调色板恒等于真源；`check-assets.mjs` 逐文件比对调色板与索引范围，色板外像素必须为 **0**（不是"≤ 5%"） | 否 |
| 2 尺寸正确 | L0 的参数 / L1 的 `@size` 即尺寸；`render-pixels.mjs` 对"矩阵行列数 ≠ `@size`"直接报错，`check-assets.mjs` 再比对清单 `spec`（**不允许近似**） | 否 |
| 3 帧对齐 | `.px.txt` 的 `@anchor` 声明内容包围盒底边中心；同一动作各帧锚点不一致即判错（见 §7.2） | 否（只做整体观感确认） |
| 4 边缘清理 | 字符矩阵天然没有抗锯齿与半透明毛边；描边色在源文件里就是明确的索引 | 否 |
| 5 无缝验证 | L0 图案基于模运算、**构造性无缝**；`check-assets.mjs` 用接缝突变比把关（超限判错），`gen-tiles.mjs` 另出 3×3 平铺预览到 `runtime/reports/` | 只看预览 |
| 6 命名与登记 | 命名由 `check-assets.mjs` 的正则把关；登记在 `assets.manifest.json`（单写者） | 需要：补 `tags` / `status` |
| 7 体积上限 | 索引色 PNG 与 PSG 合成音频天然远低于上限；校验器读实际文件体积（音频 ≤ 2 MB / 文件） | 否 |
| 8 **风格统一** | ——色板固定后色相不再漂移，但**构图、细化程度、明暗层次**无法自动判定 | **需要**：并排比对，偏差明显的重画 |

**走 L4 时额外要做的事（人工 + 脚本混合）**：

1. 把 AI 输出**量化**到 16 色并落成 `.px.txt` 或索引 PNG——**色板外像素必须为 0**，不接受"看起来接近"；
2. 免费端点出的是 JPEG，必须去伪影、重排到**精确尺寸**、重做**无缝**（它这两点都不保证）；
3. **先量化再校验**：不得把真彩 PNG 直接放进 `src/assets/`，它会被索引色校验与体积校验同时拦下。

> 判定口径：素材是否合格以 `node scripts/check-assets.mjs` 的输出为准，不以"看起来差不多"为准。

### 4.4 素材测试场景流程

在 `WorldScene` 之外做一个**独立调试场景**（开发模式按 `` ` `` 键进入，构建时剔除），用来"把所有素材放进去看整体效果"：

```
AssetPreviewScene
  ├─ A 区：瓦片平铺墙   — 每套瓦片集铺 3×3（L0 已产出平铺预览到 runtime/reports/），含四向接缝检查
  ├─ B 区：动画跑马灯   — 全部角色精灵以 8fps 循环，检查帧对齐与朝向
  ├─ C 区：UI 组件墙    — 九宫格边框、血条/灵力条、按钮三态、图标网格
  ├─ D 区：特效播放器   — 逐技能循环播放，检查帧数与色板
  ├─ E 区：昼夜对比     — 同一片瓦片分别套昼/暮/夜 tint，检查夜间可读性
  └─ F 区：色板取色器   — 实时显示当前画面的色板外像素数（口径恒为 0，见 §2.2）
```

- **这个场景现在用占位素材就能跑起来**：L0 瓦片与 L1 粒子已经产出入库，其余条目在 `assets.manifest.json` 里以 `status: planned` / `placeholder` 声明；缺失素材在场景里渲染成"深墨青底 + 血色 1px 边 + 月白 ID 文本"的**缺失占位块**，而不是静默跳过——缺素材必须看得见。
- 每批新素材入库后必须过一遍 A~F，**不通过不进入内容生产**。
- 该场景是 [15-开发路线图与里程碑](15-开发路线图与里程碑.md) M2 的退出条件之一。

### 5.2 命名规则

统一格式：`{类型}-{域}-{语义}[-{变体}].{ext}`，全小写 kebab-case，**不含中文、空格、下划线、大写**（[11-数据表规范](11-数据表规范.md) §1.1）。

| 类型前缀 | 适用范围 | 命名模板 | 示例 |
|---|---|---|---|
| `tileset-` | 瓦片集 PNG / TSX | `tileset-{区域码}-{层}` | `tileset-town-ground.png` |
| `sprite-` | 角色/敌人帧序列 | `sprite-{实体}-{动作}[-{方向}]` | `sprite-player-walk-4dir.png`、`sprite-enemy-zombie-attack.png` |
| `portrait-` | Boss 立绘 | `portrait-{实体 ID}` | `portrait-boss-shang-yang.png` |
| `icon-` | 图标（**直接复用实体 ID**） | `icon-{实体 ID}` | `icon-item-dan-zhuji.png`、`icon-skill-huo-qiu.png` |
| `ui-` | UI 组件 | `ui-{部位}-{语义}[-{状态}]` | `ui-frame-panel-9slice.png`、`ui-btn-primary-hover.png` |
| `bg-` | 场景背景 | `bg-{场景语义}` | `bg-title.png`、`bg-ending-restore.png` |
| `vfx-` | 特效帧序列 | `vfx-{技能 ID 或语义}` | `vfx-skill-huo-qiu.png` |
| `particle-` | 粒子贴图 | `particle-{天气或语义}` | `particle-rain.png` |
| `bgm-` / `sfx-` | 音频 | `bgm-{场景}` / `sfx-{动作}` | `bgm-qingyun.ogg`、`sfx-save-write.ogg` |

**矩阵源与素材 ID 的对应关系**（`pixel/` 与 `psg/`）：

| 源文件 | 命名模板 | 示例 |
|---|---|---|
| L1 单图矩阵 | `{素材 ID}.px.txt` | `src/assets/pixel/vfx/particle-spirit.px.txt` |
| L1 图集帧矩阵 | `{素材 ID}-f{序号}.px.txt`（序号从 0 起） | `sprite-player-walk-down-f00.px.txt` |
| L1 图集声明 | `{素材 ID}.atlas.json` | `sprite-player-walk-4dir.atlas.json` |
| L2 音序 | `{素材 ID}.psg.txt` | `bgm-qingyun.psg.txt` |

- **素材 ID = 产物 PNG / OGG 的文件名主干**，且必须与 `assets.manifest.json` 的 `id` 完全一致：清单里的 `id` 定义素材，文件名跟随 ID。
- 矩阵源的 `@id` 必须等于素材 ID，`@out` 必须等于清单的 `path`——不一致按校验失败处理。
- 帧矩阵**逐动作、逐方向一个文件**，文件名带上动作与方向，便于矩阵本身被 diff 与 review；被 `.atlas.json` 引用的帧矩阵不再单独出图（`render-pixels.mjs` 会跳过）。

### 5.3 与 doc/11 ID 体系的对应

| 素材 | 命名依据 | 校验规则 |
|---|---|---|
| `icon-item-*` | `items.json` 的 `item-*` | 每个可入背包的物品必须有对应图标；图标名 = `icon-` + 物品 ID |
| `icon-skill-*` | `skills.json` 的 `skill-*` | 同上 |

| `icon-enemy-*` | `enemies.json` 的 `enemy-*` / `boss-*` | 用作图鉴头像 |

## 六、瓦片集与 Tiled 对接

### 6.1 TSX 文件要求

| 项 | 要求 |
|---|---|
| `name` 属性 | 必须与地图 JSON 中引用的瓦片集名一致，且等于文件名主干（如 `tileset-town-ground`） |
| `tilewidth` / `tileheight` | 固定 `32` / `32`（不使用 16×16 或 64×64；瓦片基准尺寸见 §3.1） |
| `spacing` / `margin` | 均为 `0`；仅当瓦片需要外发光留白时才允许 `margin: 1`，且全套统一 |
| `tilecount` / `columns` | 必须与实际 PNG 精确一致，否则瓦片索引全错位；`check-assets.mjs` 按清单 `spec` 校验宽高与 `cell` |
| `image` 路径 | 相对 TSX 的路径，指向 `src/assets/tilesets/...`，不带 `../..` 越级 |
| `tileoffset` | 不使用（不用它做伪 3D 建筑偏移；建筑体积靠 `building` 层自身画） |
| 色彩 | PNG 必须是 **PNG-8 索引色**且调色板严格等于 16 色板（§2.2）；**瓦片内不得出现索引 0** |
| 自定义属性 | 允许在 `tileset` 上写 `paletteVersion`，取值取自 [`src/assets/palette.json`](../src/assets/palette.json) 的 `version` 字段，便于色板升级追踪 |

### 6.2 瓦片尺寸与层级拆分

| 层（[10-地图与区域规划](10-地图与区域规划.md) §2） | 所属瓦片集 | 说明 |
|---|---|---|
| `ground` | `tileset-{区}-ground` | 必须铺满，无空洞；水/路/草地过渡瓦片齐全 |
| `detail` | `tileset-{区}-deco` | 草叶、裂缝、血迹、纸屑；单格可叠 |
| `building` | `tileset-{区}-building` | 建筑、树、岩；含四个方向的墙沿与墙角 |
| `overhead` | 复用 `building` 瓦片集 | 屋檐、树冠；**渲染层级最高**，夜间遮挡必须正确 |
| `deco`（对象层） | 复用 `building` / `deco` | 纯装饰对象，无碰撞 |

- 瓦片集 PNG 由 L0 脚本产出（§4.1），TSX 可手写也可由脚本一并生成；**瓦片索引一经被地图引用即不可重排**——重排等于所有引用该集的地图整体错位。

### 6.3 `collision` 层绘制规范

引用 [10-地图与区域规划](10-地图与区域规划.md) §2 的三类碰撞体，绘制要求：

| 类型 | 绘制方式 | 规范 |
|---|---|---|
| `wall` | 矩形对象 | 必须沿 32 网格对齐（细节处允许 16 网格）；**连续墙面不允许留缝**；建筑碰撞体略小于可见体积（−2px）以避免"隔空撞墙"的粘滞感 |
| `water` | 矩形或多边形对象 | 必须闭合；岸边用矩形拼接，避免缝隙导致玩家"卡进水里" |
| `trigger` | 矩形对象 | 不阻挡移动；用于传送、剧情、陷阱；与 `event` 层的职责区分：`trigger` 管"物理触发"，`event` 管"事件 ID" |
| 其余 | — | `interact` / `spawn` / `event` / `encounter` 皆为对象层，**不得**画进 `collision` |

- 玩家物理体为**圆形半径 12px**（[02-核心玩法系统](02-核心玩法系统.md) §2.1），因此墙面拐角处要预留 2px 余量，避免"贴着墙角走不动"。
- 调试模式（开发构建）提供"显示碰撞体"开关，走边一圈验证无缝隙——这是 [10-地图与区域规划](10-地图与区域规划.md) §7 的验收项。

### 6.4 瓦片集大小上限

| 项 | 上限 | 超限处理 |
|---|---|---|
| 单张 PNG 文件 | **512 KB**（[13-技术架构与工程约定](13-技术架构与工程约定.md) §11） | 拆分文件（按 ground / building / deco 或按季节拆） |
| 单张瓦片图像素尺寸 | **1024×1024**（= 32×32 格 = 最多 1024 个瓦片） | 拆分为多张 TSX，并在文档记录索引段含义 |
| 单张地图引用的瓦片集数 | **≤ 6 个** | 超出说明地图该拆图了（参考 [10-地图与区域规划](10-地图与区域规划.md) §1 建议尺寸） |
| 单张地图瓦片层数 | **≤ 6 层**（4 瓦片层 + 2 对象层以上另计） | 超出需评审 |

> 索引色瓦片的体积天然很小（16 色 + 平铺图案，压缩率极高），这些上限存在的意义是防"整张地图塞进一张图"的结构问题，而不是压缩问题。

## 七、动画规范

### 7.1 标准动作集

| 动作 | 帧数 | 帧率 | 循环 | 画布 | 备注 |
|---|---|---|---|---|---|
| 站立待机 `idle` | 2 | 2 fps | 是 | 步行 | 轻微呼吸起伏 |
| 四向行走 `walk-4dir` | 4 / 向 | **8 fps** | 是 | 步行 | 每向 4 帧，共 16 帧（`left` 由镜像生成，不单独出图） |
| 攻击 `attack` | **6** | 12 fps | 否 | 战斗 | 第 3 帧为判定帧（伤害结算点） |
| 施法 `cast` | **8** | 12 fps | 否 | 战斗 | 第 5 帧为判定帧 |
| 受击 `hurt` | **2** | 12 fps | 否 | 步行 | 后仰 + 闪白一次 |
| 死亡 `die` | **6** | 10 fps | 否 | 步行 | 最后一帧保持（不消失） |
| 特殊 `special` | 8~12 | 12 fps | 否 | 战斗 | 神通 / Boss 技专属 |

> 画布列只区分两档——**步行**与**战斗**；两档的像素尺寸见 §3.1，本节不复述。

### 7.2 帧对齐与锚点规则

1. **画布固定**：一个动作的所有帧必须是同一张画布（步行档或战斗档，见 §3.1），禁止逐帧裁剪包围盒——裁剪会导致播放时抖动。
2. **锚点固定**：`originX = 0.5`，`originY = 1.0`（脚底中心）。世界内角色落地位置 = 脚底，因此战斗档的帧也必须保证脚底线与步行档一致（下缘留白 ≥ 4px）。
3. **帧对齐是"可脚本校验"的，不再靠肉眼**：每帧在 `.px.txt` 里用 `@anchor` 声明内容包围盒的**底边中心**。校验器（`check-assets.mjs` 的**帧对齐项**）据此判定三件事：
   - ① 同一动作各帧的 `@anchor` **必须完全一致**（这是硬要求，也是唯一的对齐权威）；
   - ② 每帧的 `@anchor.y` **必须等于该帧内容的实际底边 y**（保证脚踩在同一条接地线上）；
   - ③ 各帧内容包围盒的**中心 x 漂移**——这一项**只报警告，不判错**。理由：手臂与腿的摆动会合法地改变包围盒中心，硬判 0 误差会把正常动画误判为错误、逼美术把动作画僵。真正防抖动靠素材测试场景 B 区（§4.4）肉眼确认。
4. **中心 X 一致**：身体主轴（脊柱）在四向中的水平位置一致，避免"走路左右横跳"。这一项由第 3 条 ① 的 `@anchor` 一致间接保证；包围盒中心仅作漂移提示。
5. **朝向镜像**：`left` 由 `right` 水平镜像生成（Phaser `flipX`），不单独出图，也就没有对应的矩阵源。
6. **图集格式**：帧序由 `.atlas.json` 声明（`out` / `cell` / `columns` / `frames[]`，每项指向一个 `.px.txt` 帧矩阵），`render-pixels.mjs` 自动拼成**网格图集 PNG-8**；运行时用 `load.spritesheet(id, path, { frameWidth, frameHeight })` 按 `cell` 取帧，帧序号 = 声明顺序（行优先）。**不再手写 atlas JSON**，也不再产出"横向单行"的特殊布局。
7. **帧键名**：spritesheet 的帧键是数字序号；需要可读键名时在场景内建映射，键名规则沿用 `{动作}-{方向}-{序号}`（如 `walk-down-0`）。
8. **色板一致**：同一角色的所有动作共用同一块 16 色板（全局只有一块）；受击闪白用 tint / `BlendModes` 实现，**不新增色板项**。

### 7.3 战斗场景的简化表现方案

战斗**不做完整战斗动画**（预算与工作量都不允许），采用"立绘 + 位移 + 特效"三段式：

| 组成 | 表现 | 参数 |
|---|---|---|
| 角色本体 | 战斗档侧视精灵（`idle` 2 帧循环，尺寸见 §3.1） | 站在固定站位线上 |
| 出手位移 | 攻击时向前 tween 再回位 | 前进 `36px`，`120ms` 去 / `160ms` 回，缓动 `Cubic.easeOut` |
| 动作帧 | 出手瞬间叠加 `attack` / `cast` 序列（6/8 帧） | 与位移同时开始，判定帧触发伤害 |
| 受击反馈 | `hurt` 2 帧 + 精灵位移 `8px` 后退 + 闪白 `80ms` | 命中即播 |
| 特效 | 技能 `vfx-*` 叠在目标位置 | 见 §9.3 力度分级 |
| 伤害飘字 | Phaser 侧 `UIScene` 文本 | 暴击更大字号 + 血色描边 |
| 立绘使用 | **Boss 战**与**心魔战**才显示 `portrait-*`：96×96 索引图按整数倍放大（2× / 4× / 8×）铺到左侧站位区（§3.1） | 立绘出场时压暗背景 |

## 八、UI 视觉规范

### 8.1 字体

| 用途 | 首选 | 回退 | 规格 |
|---|---|---|---|
| 界面与正文 | **像素中文字体**（Zpix 最像素 / Fusion Pixel 12px） | **思源黑体 / Noto Sans SC** | 12px / 16px / 24px 三档 |
| 数字（血条、伤害） | 像素数字字体（随像素中文字体一起） | 思源黑体 Regular | 12px / 16px 加粗 |
| 汉字点阵 | 12px 点阵（保证像素感） | 16px | 关闭抗锯齿：`resolution: 1`，`padding` 为偶数 |

- **绝不使用非像素字体做主界面**；思源黑体只作为"像素中文未覆盖的字符"的回退（生僻字、异体字）。
- 字号只能是 `12` 的整数倍或 `16` 的整数倍，避免半个像素导致糊边。
- 字体属 **L3 来源**（§4.1）：中文点阵字体**不能程序化生成**，只能引入开源字体，且**必须先登记附录 A.1 再入库**（§11.2）。

### 8.2 对话框与面板边框（九宫格）

| 组件 | 切片 | 规格 |
|---|---|---|
| 对话框 `ui-frame-dialog-9slice` | 切片尺寸取自素材清单 `spec.nineSlice` | 古铜包边 + 暗青木纹底；底部留 8px 说话人名牌位 |
| 通用面板 `ui-frame-panel-9slice` | 同 `dialog` | 用于背包、技能、图鉴、存档面板 |
| 槽位 `ui-frame-slot-9slice` | 固定 48×48（不拉伸） | 物品格；选中态加 1px 灵光青描边 |
| 卡带面板 `ui-frame-save-9slice` | 同 `panel` | 存档槽专用，右上角留"指示灯"小方孔 |

- 九宫格拉伸**只允许整数倍或按边平铺**，禁止自由缩放（会把边框拉成非整数像素）。
- 面板底纹必须是索引色硬色块 + Bayer 抖动，**禁止渐变**（§2.2 禁止衍生色）。
- 面板内边距统一 `16px`，面板间距 `12px`。
- **切片尺寸的真源是素材清单的 `spec.nineSlice`（当前 `16`）**，本节不复述具体数字。48×48 的画布在 `16` 切片下中心恰好剩 16px；历史上出现过的「四角 32 / 四边 24」是更大画布时期的数值，**若未来调整画布尺寸必须同步改清单**，否则切片会算成负中心。
- **面板中心是不透明的**（暗青木纹底），**不做镂空** —— UI 面板需要遮挡身后的世界画面。因此 `ui-frame-*` 只在四角的 2px 倒角处使用索引 0（透明），面板主体与 `deco` 瓦片整幅不透明（暗底用深墨青索引 1）。

### 8.3 血条 / 灵力条 / 心境条

| 条 | 底槽 | 填充 | 特殊 |
|---|---|---|---|
| 生命 `ui-bar-hp` | 深墨青 | 血色（亮阶用 Bayer 抖动混入暮橙） | `< 30%` 时条体以 2Hz 脉冲 |
| 灵力 `ui-bar-mp` | 深墨青 | 灵光青（暗阶用 Bayer 抖动混入夜蓝） | 灵力不足时按钮置灰并闪条 |
| 心境 `ui-bar-mind` | 深墨青 | 符纸黄 | `< 30` 时条体边缘泛血色 |
| 修为 `ui-bar-exp` | 深墨青 | 月白 | 满值时整条呼吸发光（两帧交替） |

- 条体高 8px（HUD）/ 12px（战斗界面），外框 1px 深墨青。
- **不用渐变色条**，只用两段硬色块 + 1px 高光行，保持像素感；色名对应的色值见 §2.1，**明暗一律靠 Bayer 4×4 抖动**，不再使用"衍生 ±15% 明度"的旧做法（§2.2）。

### 8.4 图标风格

1. 尺寸按 §3.1 的两档出图（列表用 32×32、详情与技能用 64×64），**1px 深墨青描边**，透明背景，图形占满内容区（32×32 档占 28×28）。
2. 光源统一自**左上 45°**；所有图标共用同一明暗层次（亮面 / 中间色 / 暗面 三阶）。
3. 品质用**外框色**表达，不改图标本体：凡品石灰、良品苔绿、珍品夜蓝、灵品血色、神品符纸黄、仙品月白（色值见 §2.1，对应 [11-数据表规范](11-数据表规范.md) §3.1 的稀有度）。
4. 图标不得含文字、不得含数字。
5. 图标源为 `.px.txt`（L1），因此天然满足色板与描边规则，不需要逐张手工取色。

### 8.5 按钮三态

| 状态 | 表现 |
|---|---|
| 常态 | 暗青底 + 古铜 1px 边 + 月白文字 |
| 悬停 | 古铜边换成符纸黄，另加 1px 亮边（**不烘焙新图**，用 tint / 叠边实现，避免衍生色） |
| 按下 | 内容整体下移 `2px`，边宽 2px（**不烘焙新图**，靠位移表达） |
| 禁用 | 换用石灰系描边 + `alpha 0.5`，不响应悬停 |

- 焦点（键盘操作）：在古铜边外再加 1px 灵光青描边，保证手柄/键盘可见。
- 按钮音：悬停可选（默认关）；点击 / 确认 / 取消各一条音效（ID 见 §10.3）。
- **三态不各出一张 PNG**：位图只有一张常态图，其余状态由引擎 tint、位移与叠边实现——这与 §2.2 的索引色锁一致（明度变化无法烘焙成 16 色板内的新图）。

### 8.6 分辨率与缩放策略

| 项 | 方案 |
|---|---|
| 逻辑分辨率 | **640×360**（16:9），所有 UI 按此尺寸布局 |
| 缩放 | **整数倍缩放**：`1×`(640×360) / `2×`(1280×720) / `3×`(1920×1080) / `4×`(2560×1440)；取当前窗口能容纳的最大整数倍 |
| 非整数窗口 | 留黑边（letterbox）居中，**绝不使用 1.5× 这类非整数缩放** |
| Phaser 配置 | `pixelArt: true`、`roundPixels: true`、`antialias: false`、`scale.mode: Phaser.Scale.FIT` + `autoCenter: CENTER_BOTH` |
| CSS | 画布 `image-rendering: pixelated`（Safari 加 `-webkit-optimize-contrast`） |
| 大屏适配 | ≥ 1920 宽时可在 `UIScene` 外侧加装饰性古铜边框填满黑边；背景用程序化多层视差层（§3.1），层随缩放整数放大 |
| 小屏（手机竖屏） | 提示"横屏游玩体验更好"，仍可玩；UI 面板自动改为全屏抽屉 |
| 文本 | 文本对象 `resolution = 游戏缩放倍数的整数`（1×→1，2×→2），避免文字被系统二次采样 |

## 九、特效与氛围

### 9.1 昼夜 tint 参数

引用 [10-地图与区域规划](10-地图与区域规划.md) §4.1 的四段表现，落地为全局 `tint`（一层覆盖，不做逐光源光照）：

| 视觉段 | 时辰 | 覆盖色 | alpha | 额外层 |
|---|---|---|---|---|
| 晨 | 卯~辰 | `#ffd9a0`（暖橙白） | `0.10` | 无 |
| 昼 | 巳~未 | `#ffffff`（无色） | `0.00` | 无 |
| 暮 | 申~酉 | 暮橙（见 §2.1） | `0.18` | 无 |
| 夜 | 戌~寅 | `#5a6a9a`（对应 [11-数据表规范](11-数据表规范.md) §5.6 的 `night` tint） | `0.45` | 灯火遮罩：在存档点、客栈、商店位置叠符纸黄（见 §2.1）alpha 0.20 的圆形光斑 |

- tint 是**引擎层覆盖色**，不落盘为位图，因此不受索引色锁的约束（§2.2 管的是位图）；但它盖在索引画面上会改变观感，**夜 / 暮两档必须逐张地图验收**。
- 过渡：相邻时段切换用 `1200ms` 线性补间（`SceneTransition` 期间不切换，避免叠加）。
- 夜间必须逐张地图验收"`overhead` 层遮挡正确、`ground` 不糊成一团"（[10-地图与区域规划](10-地图与区域规划.md) §7）。

### 9.2 天气粒子

| 天气 | 粒子贴图 | 数量 | 行为 | 附加 |
|---|---|---|---|---|
| 雨 | `particle-rain`（2×8） | 200 | 下落 `380 px/s`，轻微左偏 | 地面溅点每 400ms 一次；`sfx-rain-ambient` 循环 |
| 雷雨 | 同上 | 260 | 同上 | 每 6~14s 一次全屏白闪 `120ms` + `sfx-thunder-ambient` |
| 雪 | `particle-snow`（3×3） | 140 | 下落 `70 px/s` + 正弦横摆 | 落地淡出，不留痕 |
| 雾 | 4 张大雾贴图（512×256） | 4 层 | 横向缓慢平移 `8 px/s` | alpha `0.25`，视口四角更浓（"视野缩小"） |
| 晴 / 阴 | 无 | 0 | — | 阴天把全局 tint 额外压 `alpha 0.08` 的青灰 |

- 粒子贴图必须是 PNG-8 索引色单帧（§3.1）；来源按 §4.1 选择——几何形态走 L0、手绘形态走 L1，两条路都算合规。
- 粒子总预算：**任意时刻 ≤ 300 个**；低端设备（帧率持续 `< 45`）自动降到 50%。
- 天气切换在跨日刷新时发生，粒子用 `800ms` 淡入淡出，不做突变。

### 9.3 战斗特效力度分级

| 级别 | 用于 | 帧数 / 尺寸 | 屏震 | 顿帧 | 闪光 |
|---|---|---|---|---|---|
| **L1 轻** | 普攻命中、单体贴符 | ≤ 8 帧 / 64×64 | 无 | 无 | 无 |
| **L2 中** | 常规技能、群体技 | ≤ 16 帧 / 64×64 | `2px / 80ms` | 无 | 轻微 |
| **L3 重** | Boss 技、天劫、突破、神通 | ≤ 32 帧 / 128×128 | `6px / 240ms` | `80ms` | 全屏白闪 `120ms` |
| **L4 演出** | 剧情战阶段切换、结局 | 不限（单独制作） | `8px / 320ms` | `120ms` | 允许色偏 |

> **编号澄清**：本节讲的是**特效力度分级**（轻 / 中 / 重 / 演出），与 §4.1 的**素材来源分级**（L0 ~ L4）是两套互不相干的编号——前者描述"打起来多响"，后者描述"素材从哪来"，不要混用。

### 9.4 屏震与顿帧的使用节制

1. **单场战斗**：屏震累计 ≤ 6 次；同一次屏震结束后至少间隔 `400ms` 才允许下一次。
2. **顿帧**：单场 ≤ 3 次，单次 ≤ `120ms`；顿帧期间**输入与计时全停**（不能出现"顿帧后连招出血"）。
3. **L3 以上特效**：同屏不得同时播放两个（排队），避免闪烁伤害视觉。
4. **可访问性**：设置面板提供「减弱屏幕震动」（屏震幅度 ×0.4，L3 降为 L1 表现）与「减少闪光」（取消全屏白闪，改为描边发光），默认**跟随系统 `prefers-reduced-motion`**。
5. **禁止**：连续屏震（"摇成筛子"）、战斗全程常驻震屏、用屏震掩盖动画帧缺失。

## 十、音频规范

### 10.1 PSG 通道模型、音序源与音量分轨

音频走 **L2 PSG 合成**（§4.1）：不是"找素材、剪素材"，而是写音序、由脚本合成——因此音频和位图一样可 diff、可 review、可幂等重出。

**通道模型**（对齐卡带机的 GB 四通道硬件）：

| 通道 | 波形 | 职责 | 备注 |
|---|---|---|---|
| CH1 | 方波，占空比 **12.5% / 25% / 50% / 75% 可调** | 主旋律 | 12.5% 更"尖"（笛、剑鸣），50% 更"厚"（齐奏、和弦） |
| CH2 | 方波，占空比同上 | 和声 / 对位 / 应答句 | 与 CH1 错开占空比，避免两条旋律同质化 |
| CH3 | 三角波（无占空比） | 低音 / 贝斯线 | 唯一天然柔和的通道，负责"稳" |
| CH4 | 噪声（LFSR） | 打击 / 环境质感 | 移位寄存器宽度决定音色：窄 = 金属/木鱼/铃，宽 = 白噪/风雨 |

**源文件 `.psg.txt`**（文本音序，入库；与 `.px.txt` 同为"可读、可 diff 的源"）：

```
# bgm-qingyun.psg.txt —— 青云镇
@id      bgm-qingyun
@out     src/assets/audio/bgm/bgm-qingyun.ogg
@tempo   96                 # BPM，决定 1/4 音符的采样帧数
@loop    90s                # 循环长度，合成时取整到整数小节
@tuning  A4=440
---
# 通道参数行：w=占空比(%)  env=起振,衰减,保持,释放(ms)  noise=white|metal
CH1  w=25   env=0,0,900,120
CH2  w=50   env=0,0,900,160
CH3  env=0,0,1200,200
CH4  noise=white  env=0,40,0,60
# 音符行：{通道} {音名|休止} {时值} {音量0-15} {效果}
CH1  D5   1/8    v=12
CH1  A4   1/8    v=10  slide=-2
CH3  D3   1/2    v=9
CH4  -    1/16   v=6
CH2  F5   1/4    v=8   arp=D5,A5
```

| 元素 | 写法 | 说明 |
|---|---|---|
| 元数据 | `@id` / `@out` / `@tempo` / `@loop` / `@tuning` | 首部，`---` 之前；`@out` 必须等于素材清单的 `path` |
| 通道参数 | `CH1`~`CH4` + `w=` / `env=` / `noise=` | `w` 仅方波；`noise` 仅 CH4；`env` 为 ADSR 四段毫秒 |
| 音符行 | `{通道} {音名或 -} {时值} {音量} {效果}` | 音名如 `C4` / `D#5`，休止写 `-`；时值用分数（`1/4`、`1/8.` 附点） |
| 音量 | `v=0~15` | 与 GB 的 4 位音量一致 |
| 效果 | `slide=` 滑音 / `arp=` 琶音 / `vib=` 颤音 / `retrig` 重触发 | 可省略 |

- 合成：`scripts/gen-audio.mjs` 用 node 内置模块按音序合成 PCM（方波 / 三角 / 噪声 + 包络），再调用 **ffmpeg**（本环境 8.1.2 可用，无 sox / ImageMagick）转 OGG Vorbis 落盘；中间 WAV 只写 `runtime/tmp/`，不入库。
- **BGM 的无缝循环由合成时对齐首尾相位与包络保证**：脚本把 `@loop` 长度取整到整数小节，并让末小节的各通道相位与包络值收束回首小节的状态——**不靠试听**；校验器比对首尾 100ms 的能量差（RMS），差值必须为 0。

**音量分轨**：

| 轨 | 默认音量 | 存储 | 说明 |
|---|---|---|---|
| BGM | `0.70` | `ec:settings:v1` 的 `bgmVolume` | 环境与战斗音乐 |
| SFX | `0.80` | `sfxVolume` | 战斗、脚步、交互、环境音 |
| UI | `0.80` | `uiVolume` | 按钮、面板、提示音 |

- 三条独立 `GainNode`，设置面板三个滑块（0~100，步进 5）；主音量不单独做，避免"双重衰减"。
- 切场景时 BGM 交叉淡出/淡入 `800ms`；战斗进入用 `300ms` 加速淡入（要"切入感"）。
- 页面失去焦点自动把 BGM 降到 `0.3`，恢复时回升（避免切标签页时吵人）。

3. **人工创作叠加**：L4 素材必须经过 §4.3 的**量化与校验**（量化到 16 色、色板外像素为 0、重排尺寸与无缝，必要时落成 `.px.txt`），生成物在最终素材中的贡献需在附录 A.2 如实标注（生成 + 量化 + 人工重绘 / 仅参考未入库）。
4. **禁止入库**：来源不明、条款不允许商用、或无法追溯到具体模型与日期的 AI 素材，一律不入库。
5. **可追溯性**：附录 A.2 必须能回答"这张图是哪天、用哪个模型、什么提示词生成的，量化后落在哪个源文件"。

### 11.2 第三方素材登记要求

任何非本团队原创、非本项目脚本生成的素材（**字体**、音效、占位图、图标、Shader）入库前必须在本文件**附录 A.1** 登记以下字段，缺一不可：

| 字段 | 要求 |
|---|---|
| 名称 | 素材/库的正式名称 + 版本号或文件哈希 |
| 来源 | 下载 URL 或仓库地址 |
| 许可证 | 如 `SIL OFL 1.1`、`CC0-1.0`、`CC-BY-4.0`、`MIT` |
| 作者 | 原始作者或组织 |
| 用途 | 用在哪（字体 / UI / 音效 / 占位） |
| 署名要求 | 是否需要在游戏内或 README 署名，以及署名文案 |
| 入库日期 | 该文件进入 `src/assets/` 或 `public/` 的日期 |

硬规则：

1. **未登记不得入库**（与 [13-技术架构与工程约定](13-技术架构与工程约定.md) §8.1 禁止项对齐）。
2. `CC-BY-*` 类素材必须把署名写进游戏"关于"页与 `README.md`。
3. 占位素材也必须登记；一旦替换为正式素材，把该行标记为 `[已替换 · 日期]` 而**不删除**，保留来源追溯。
4. **点阵中文字体**：中文点阵字体**不能程序化生成**——汉字集规模与字形复杂度决定了它必须由人设计、历经多年迭代，脚本合成不出可读的字形。因此它只能走 **L3**：必须引入**开源点阵中文字体**（github 可达，如 Zpix、Fusion Pixel），**优先 SIL OFL 授权**；字体文件与许可证文本同时入库，且**必须先登记进附录 A.1——未登记不得入库**。字号与回退策略见 §8.1。
5. **字体授权单独列出**：字体最容易踩坑（"免费商用"字样但实际限制嵌入），登记时必须同时写明是否允许 Web 嵌入。
