## 一、视觉定位

### 1.1 一句话美术主张

> **在灵气死去的世界里，用最省的 12 种颜色，画出青苔爬上铜器的那种旧。**

### 1.2 定位说明

| 维度 | 定位 | 反面（禁止） |
|---|---|---|
| 基调 | **末法时代的暗青 + 古铜 + 月白**：整体偏冷、偏灰、低饱和，高饱和只留给灵光与血 | 明亮卡通、糖果色、渐层厚涂 |
| 风格 | 像素风，32×32 瓦片基准，硬边像素、无抗锯齿、无软阴影 | 半写实厚涂、3D 渲染感、模糊滤镜 |
| 氛围 | "仙门衰败"：褪色的幡、生锈的铜、半塌的屋檐、夜里的一点灯火 | 仙气飘飘的明亮天宫、饱满繁华市集 |
| 对比 | 冷底（暗青）压场，暖点（符纸黄、灯火）叙事，灵光青只用于**灵力与阵纹** | 各色乱用、灵气到处发光 |
| 情绪 | 安静、克制、略带衰败的温柔 | 恐怖血腥、刺激夸张 |

### 1.3 视觉三原则

1. **旧而不脏**：做旧靠"褪色 + 铜锈 + 磨损边"，不靠噪点糊图。
2. **省色不省意**：任何一块瓦片只用调色板内颜色，但要能一眼看出"这是茅山的符纸味"还是"这是昆仑的雪线"。
3. **夜色是主角**：本作一半时间在夜里跑，夜间的可读性优先于白天好看。

### 2.2 衍生色与锁定规则

| 规则 | 内容 |
|---|---|
| 允许的衍生 | 每个标准色允许 `±15%` 明度的**明暗过渡色**（用于瓦片边缘过渡与 3~4 阶明暗），上限 `12 × 2 = 24` 个衍生色 |
| 禁止的衍生 | 禁止改色相、禁止提高饱和度超过基准 `+10%`、禁止新增第 13 个基色 |
| 强制约束 | AI 生成提示词必须带"统一调色板"；生成后必须用取色器抽查，落在色板外的像素**一律手动替换**（不允许"整体调色板映射"一把梭，会毁掉金属质感） |
| 例外通道 | 仅在**结局演出**与**血月**两张场景允许 `+2` 临时色（`#c9713a` 暮橙、`#d9e8ea` 冷白）；用后即弃，不进常规素材 |
| 校验 | 生成后的瓦片集/精灵图跑一次取色统计，色板外颜色占比 `> 5%` 即判定不合格（统计脚本放 `runtime/tools/`，报告放 `runtime/reports/`，见 [13-技术架构与工程约定](13-技术架构与工程约定.md) §7） |

### 2.3 语义用色约定

| 语义 | 色 | 说明 |
|---|---|---|
| 灵力 / 阵法 / 灵力条 | 灵光青 `#4fd1c5` | 全游戏唯一"发光的青" |
| 生命 / 伤害 / 危险 | 血色 `#8f2b2b` | 不加渐变白，直接硬色块 |
| 心境 / 符箓 / 暖光 | 符纸黄 `#e0c070` | 心魔类场景反用（心境低时 UI 边缘泛黄） |
| 妖鬼 / 夜间敌人 / 鬼魂 | 夜蓝 `#2a3a5c` | 与丧尸类区分：僵尸偏苔绿+暗铜，鬼魂偏夜蓝 |
| 正道 / 昆仑 | 月白 + 青灰 | 冷、干净、少装饰 |
| 截教 / 禁术 | 血色 + 深墨青 | 强对比、脏边 |
| 凡人 / 王朝 | 古铜 + 符纸黄 | 暖、市井、有生活气 |

## 三、素材规格表

### 3.1 通用规格

| 类型 | 尺寸 | 格式 | 上限 | 备注 |
|---|---|---|---|---|
| 地图瓦片 | **32×32** | PNG 瓦片集 + TSX | 单文件 ≤ 512 KB | 无缝可拼；分层拆文件（ground / building / deco） |
| 角色精灵 | **32×48**（步行）、**48×48**（战斗） | PNG 帧序列 / 图集 | ≤ 1 MB | 透明背景，帧对齐同一画布 |
| Boss 精灵 | **96×96** | PNG 帧序列 | ≤ 1.5 MB | 出场演出可用放大的 48×48 |
| Boss 立绘 | **768×1024** | PNG（背景可透明） | ≤ 1.5 MB | 战斗左侧半身像，构图右留白 |
| NPC / 同伴精灵 | 32×48 | PNG 帧序列 | ≤ 512 KB | 与玩家同规格，便于共用锚点 |
| UI 图标 | **32×32**（背包/列表）、**64×64**（详情/技能） | PNG | ≤ 64 KB | 透明背景，居中，1px 描边（深墨青） |
| 场景背景 | **1920×1080** | PNG / JPG(质量 82) | ≤ 800 KB | 主菜单、结局、章节标题用；不做地图背景 |
| 战斗特效帧 | **64×64**（技能）、**128×128**（Boss/天劫） | PNG 帧序列 | ≤ 512 KB/技能 | 帧数 8~32，透明背景 |
| 粒子贴图 | **8×8 / 16×16 / 32×32** | PNG 单帧 | ≤ 16 KB | 雨滴 2×8、雪花 3×3、火星 3×3 等 |
| 符箓小游戏图层 | 512×512 底图 + 32×32 符纹印章 + 64×64 符笔 | PNG | ≤ 512 KB 合计 | 分层：纸底 / 符纹 / 笔迹 / 评分高亮 |
| PWA 图标 | 见 §3.2 | PNG | ≤ 100 KB | 全量入 `public/icons/` |

### 3.2 PWA 图标尺寸清单

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `icon-192.png` | 192×192 | PWA `any` purpose |
| `icon-512.png` | 512×512 | PWA 启动图 / 安装弹窗 |
| `icon-192-maskable.png` | 192×192 | Android 自适应图标（内容留在中央 80% 安全区） |
| `icon-512-maskable.png` | 512×512 | Android 启动画面 |
| `apple-touch-icon.png` | 180×180 | iOS 添加到主屏 |
| `favicon-32.png` | 32×32 | 浏览器标签页 |
| `favicon-16.png` | 16×16 | 兼容旧浏览器 |

- 图标主视觉：**镇口残碑 + 一点灵光青**；背景用暗青 `#1d3b45`，描边深墨青。
- 图标必须是"小尺寸可辨认"的：16×16 下只需看出"一块碑 + 一点青光"。

### 3.3 尺寸硬规则

1. **一切像素坐标为整数**；瓦片、图标、粒子的宽高必须是 2 的幂或 32 的倍数（8 的倍数可接受）。
2. **禁止放大位图**：32×48 精灵不得直接拉伸到 64×96，需要大图就重新生成。
3. **禁止在引擎内做滤镜**：不用模糊、发光、投影等会破坏像素硬边的效果；发光用"多层同心色块 + 低 alpha"手做。
4. **单文件上限**（[13-技术架构与工程约定](13-技术架构与工程约定.md) §11）：瓦片集 ≤ 512 KB、精灵图 ≤ 1 MB、音频单文件 ≤ 2 MB；超限必须拆分或压缩。

## 四、AI 生成管线

### 4.1 四个模型的分工

| 模型 | 定位 | 使用场景 | 不用于 |
|---|---|---|---|
| **rd-tile** | 瓦片地图 | 城镇地面/建筑/装饰、野外植被与地形、秘境砖石、室内家具 | 角色、UI 图标 |
| **rd-animation** | 动画精灵 | 玩家/NPC/敌人的四向行走、攻击、施法、受击、死亡序列帧 | 静态背景、大面积场景 |
| **rd-plus** | 高质量场景 / UI | UI 面板与边框、物品/技能图标、章节背景、Boss 立绘、结局插画 | 需要严格无缝拼接的瓦片 |
| **rd-fast** | 快速迭代 | 风格试色、批量出 20 个图标草稿、调色板验证、特效帧草稿 | 最终入库素材（必须经 rd-plus/rd-animation 重出或人工重绘） |

### 4.3 生成后的人工后期（强制）

AI 出图**一律视为草稿**，入库前必须完成：

| 步骤 | 具体要求 | 检查方式 |
|---|---|---|
| 1 取色归一 | 把色板外颜色替换为最接近的标准色或衍生色 | 取色统计，色板外占比 ≤ 5% |
| 2 帧对齐 | 逐帧统一画布尺寸与锚点（脚底水平线一致、中心 X 一致），消除抖动 | 在素材测试场景里循环播放，肉眼无抖动 |
| 3 边缘清理 | 去半透明毛边、去抗锯齿灰边、去 1px 杂点；描边统一深墨青 | 放大 800% 检查 |
| 4 风格统一 | 与已入库素材并排比对明度与细化程度，偏差明显者重绘 | 素材测试场景并排 |
| 5 无缝验证 | 瓦片四向平铺 3×3 检查接缝 | 平铺预览 |
| 6 命名与登记 | 按 §5 命名，登记进附录 A.2 | 目录与附录一致 |

### 4.4 素材测试场景流程

在 `WorldScene` 之外做一个**独立调试场景**（开发模式按 `` ` `` 键进入，构建时剔除），用来"把所有生成的资源放进去看整体效果"：

```
AssetPreviewScene
  ├─ A 区：瓦片平铺墙   — 每套瓦片集铺 3×3，含四向接缝检查
  ├─ B 区：动画跑马灯   — 全部角色精灵以 8fps 循环，检查帧对齐与朝向
  ├─ C 区：UI 组件墙    — 九宫格边框、血条/灵力条、按钮三态、图标网格
  ├─ D 区：特效播放器   — 逐技能循环播放，检查帧数与色板
  ├─ E 区：昼夜对比     — 同一片瓦片分别套昼/暮/夜 tint，检查夜间可读性
  └─ F 区：色板取色器   — 实时显示当前画面色板外颜色占比
```

- 每批新素材入库后必须过一遍 A~F，**不通过不进入内容生产**。
- 该场景是 [15-开发路线图与里程碑](15-开发路线图与里程碑.md) M2 的退出条件之一。

### 5.2 命名规则

统一格式：`{类型}-{域}-{语义}[-{变体}].{ext}`，全小写 kebab-case，**不含中文、空格、下划线、大写**（[11-数据表规范](11-数据表规范.md) §1.1）。

| 类型前缀 | 适用范围 | 命名模板 | 示例 |
|---|---|---|---|
| `tileset-` | 瓦片集 PNG / TSX | `tileset-{区域码}-{层}` | `tileset-town-ground.png` |
| `sprite-` | 角色/敌人帧序列 | `sprite-{实体}-{动作}[-{方向}]` | `sprite-player-walk-4dir.png`、`sprite-enemy-zombie-attack.png` |
| `portrait-` | Boss 立绘 | `portrait-{实体 ID}` | `portrait-boss-shang-yang.png` |
| `icon-` | 图标（**直接复用实体 ID**） | `icon-{实体 ID}` | `icon-item-dan-zhuji.png`、`icon-skill-huo-qiu.png` |
| `ui-` | UI 组件 | `ui-{部位}-{语义}[-{状态}]` | `ui-frame-panel-9slice.png`、`ui-btn-primary-hover.png` |
| `bg-` | 场景背景 | `bg-{场景语义}` | `bg-title.png`、`bg-ending-restore.png` |
| `vfx-` | 特效帧序列 | `vfx-{技能 ID 或语义}` | `vfx-skill-huo-qiu.png` |
| `particle-` | 粒子贴图 | `particle-{天气或语义}` | `particle-rain.png` |
| `bgm-` / `sfx-` | 音频 | `bgm-{场景}` / `sfx-{动作}` | `bgm-qingyun.ogg`、`sfx-save-write.ogg` |

### 5.3 与 doc/11 ID 体系的对应

| 素材 | 命名依据 | 校验规则 |
|---|---|---|
| `icon-item-*` | `items.json` 的 `item-*` | 每个可入背包的物品必须有对应图标；图标名 = `icon-` + 物品 ID |
| `icon-skill-*` | `skills.json` 的 `skill-*` | 同上 |
| `icon-fac-*` | `factions` 的 `fac-*` | 六势力声望徽记 |
| `icon-enemy-*` | `enemies.json` 的 `enemy-*` / `boss-*` | 用作图鉴头像 |
| `sprite-enemy-*` | `enemies.json` 的 `enemy-*` | 地图上的敌人必须有四向行走 |
| `bgm-*` / `sfx-*` | [11-数据表规范](11-数据表规范.md) §2 已登记的音频前缀 | 地图的 `ambient.bgm` 必须指向存在的 `bgm-*` |
| `tileset-*` | [10-地图与区域规划](10-地图与区域规划.md) §1 的区域瓦片集列 | 地图 JSON 的 `tileset` 字段必须能在本目录解析到 |

> 校验方式：素材文件名与配置表 ID 的一致性检查脚本放 `runtime/tools/`（[13-技术架构与工程约定](13-技术架构与工程约定.md) §7.4）；**缺图标/缺 BGM 属于构建期错误**，不允许带着缺失上线。

## 六、瓦片集与 Tiled 对接

### 6.1 TSX 文件要求

| 项 | 要求 |
|---|---|
| `name` 属性 | 必须与地图 JSON 中引用的瓦片集名一致，且等于文件名主干（如 `tileset-town-ground`） |
| `tilewidth` / `tileheight` | 固定 `32` / `32`（不使用 16×16 或 64×64） |
| `spacing` / `margin` | 均为 `0`；仅当瓦片需要外发光留白时才允许 `margin: 1`，且全套统一 |
| `tilecount` / `columns` | 必须与实际 PNG 精确一致，否则瓦片索引全错位 |
| `image` 路径 | 相对 TSX 的路径，指向 `src/assets/tilesets/...`，不带 `../..` 越级 |
| `tileoffset` | 不使用（不用它做伪 3D 建筑偏移；建筑体积靠 `building` 层自身画） |
| 自定义属性 | 允许在 `tileset` 上写 `paletteVersion: 1`，便于后续色板升级追踪 |

### 6.2 瓦片尺寸与层级拆分

| 层（[10-地图与区域规划](10-地图与区域规划.md) §2） | 所属瓦片集 | 说明 |
|---|---|---|
| `ground` | `tileset-{区}-ground` | 必须铺满，无空洞；水/路/草地过渡瓦片齐全 |
| `detail` | `tileset-{区}-deco` | 草叶、裂缝、血迹、纸屑；单格可叠 |
| `building` | `tileset-{区}-building` | 建筑、树、岩；含四个方向的墙沿与墙角 |
| `overhead` | 复用 `building` 瓦片集 | 屋檐、树冠；**渲染层级最高**，夜间遮挡必须正确 |
| `deco`（对象层） | 复用 `building` / `deco` | 纯装饰对象，无碰撞 |

### 6.3 `collision` 层绘制规范

引用 [10-地图与区域规划](10-地图与区域规划.md) §2 的三类碰撞体，绘制要求：

| 类型 | 绘制方式 | 规范 |
|---|---|---|
| `wall` | 矩形对象 | 必须沿 32 网格对齐（细节处允许 16 网格）；**连续墙面不允许留缝**；建筑碰撞体略小于可见体积（−2px）以避免"隔空撞墙"的粘滞感 |
| `water` | 矩形或多边形对象 | 必须闭合；岸边用矩形拼接，避免缝隙导致玩家"卡进水里" |
| `trigger` | 矩形对象 | 不阻挡移动；用于传送、剧情、陷阱；与 `event` 层的职责区分：`trigger` 管"物理触发"，`event` 管"事件 ID" |
| 其余 | — | `interact` / `spawn` / `event` / `encounter` 皆为对象层，**不得**画进 `collision` |

- 玩家物理体为**圆形半径 12px**（[02-核心玩法系统](02-核心玩法系统.md) §2.1），因此墙面拐角处要预留 2px 余量，避免"贴着墙角走不动"。
- 调试模式（开发构建）提供"显示碰撞体"开关，走边一圈验证无缝隙——这是 [10-地图与区域规划](10-地图与区域规划.md) §7 的验收项。

### 6.4 瓦片集大小上限

| 项 | 上限 | 超限处理 |
|---|---|---|
| 单张 PNG 文件 | **512 KB**（[13-技术架构与工程约定](13-技术架构与工程约定.md) §11） | 拆分文件（按 ground / building / deco 或按季节拆） |
| 单张瓦片图像素尺寸 | **1024×1024**（= 32×32 格 = 最多 1024 个瓦片） | 拆分为多张 TSX，并在文档记录索引段含义 |
| 单张地图引用的瓦片集数 | **≤ 6 个** | 超出说明地图该拆图了（参考 [10-地图与区域规划](10-地图与区域规划.md) §1 建议尺寸） |
| 单张地图瓦片层数 | **≤ 6 层**（4 瓦片层 + 2 对象层以上另计） | 超出需评审 |

## 七、动画规范

### 7.1 标准动作集

| 动作 | 帧数 | 帧率 | 循环 | 画布 | 备注 |
|---|---|---|---|---|---|
| 站立待机 `idle` | 2 | 2 fps | 是 | 32×48 | 轻微呼吸起伏 |
| 四向行走 `walk-4dir` | 4 / 向 | **8 fps** | 是 | 32×48 | 每向 4 帧，共 16 帧，横向排列 |
| 攻击 `attack` | **6** | 12 fps | 否 | 48×48 | 第 3 帧为判定帧（伤害结算点） |
| 施法 `cast` | **8** | 12 fps | 否 | 48×48 | 第 5 帧为判定帧 |
| 受击 `hurt` | **2** | 12 fps | 否 | 32×48 | 后仰 + 闪白一次 |
| 死亡 `die` | **6** | 10 fps | 否 | 32×48 | 最后一帧保持（不消失） |
| 特殊 `special` | 8~12 | 12 fps | 否 | 48×48 | 神通 / Boss 技专属 |

### 7.2 帧对齐与锚点规则

1. **画布固定**：一个动作的所有帧必须是同一张画布尺寸（32×48 或 48×48），禁止逐帧裁剪包围盒——裁剪会导致播放时抖动。
2. **锚点固定**：`originX = 0.5`，`originY = 1.0`（脚底中心）。世界内角色落地位置 = 脚底，因此 48×48 的战斗帧也要保证脚底线与 32×48 帧一致（下缘 ≥ 4px 留白）。
3. **脚底线一致**：行走 4 帧的脚底最低像素必须落在同一行，误差 0 行。
4. **中心 X 一致**：身体主轴（脊柱）在四向中的水平位置一致，避免"走路左右横跳"。
5. **朝向镜像**：`left` 由 `right` 水平镜像生成（Phaser `flipX`），不单独生成，节省素材与保证对称。
6. **图集格式**：帧序列导出为**横向单行 PNG**，配 Phaser atlas JSON；帧键名 `{动作}-{方向}-{序号}`（如 `walk-down-0`）。
7. **色板一致**：同一角色的所有动作必须同色板；受击闪白不做成第 13 色，而用白化（`BlendModes` / tint）实现。

### 7.3 战斗场景的简化表现方案

战斗**不做完整战斗动画**（预算与工作量都不允许），采用"立绘 + 位移 + 特效"三段式：

| 组成 | 表现 | 参数 |
|---|---|---|
| 角色本体 | 48×48 侧视精灵（idle 2 帧循环） | 站在固定站位线上 |
| 出手位移 | 攻击时向前 tween 再回位 | 前进 `36px`，`120ms` 去 / `160ms` 回，缓动 `Cubic.easeOut` |
| 动作帧 | 出手瞬间叠加 `attack` / `cast` 序列（6/8 帧） | 与位移同时开始，判定帧触发伤害 |
| 受击反馈 | `hurt` 2 帧 + 精灵位移 `8px` 后退 + 闪白 `80ms` | 命中即播 |
| 特效 | 技能 `vfx-*` 叠在目标位置 | 见 §9.3 力度分级 |
| 伤害飘字 | Phaser 侧 `UIScene` 文本 | 暴击更大字号 + 血色描边 |
| 立绘使用 | **Boss 战**与**心魔战**才显示 `portrait-*`（768×1024），普通战斗只用 48×48 精灵 | 立绘出场时压暗背景 |

## 八、UI 视觉规范

### 8.1 字体

| 用途 | 首选 | 回退 | 规格 |
|---|---|---|---|
| 界面与正文 | **像素中文字体**（Zpix 最像素 / Fusion Pixel 12px） | **思源黑体 / Noto Sans SC** | 12px / 16px / 24px 三档 |
| 数字（血条、伤害） | 像素数字字体（随像素中文字体一起） | 思源黑体 Regular | 12px / 16px 加粗 |
| 汉字点阵 | 12px 点阵（保证像素感） | 16px | 关闭抗锯齿：`resolution: 1`，`padding` 为偶数 |

- **绝不使用非像素字体做主界面**；思源黑体只作为"像素中文未覆盖的字符"的回退（生僻字、异体字）。
- 字号只能是 `12` 的整数倍或 `16` 的整数倍，避免半个像素导致糊边。
- 字体授权见附录 A.1。

### 8.2 对话框与面板边框（九宫格）

| 组件 | 切片 | 规格 |
|---|---|---|
| 对话框 `ui-frame-dialog-9slice` | 上下边 24px / 左右边 24px / 中心 1×1 | 古铜包边 + 暗青木纹底；底部留 8px 说话人名牌位 |
| 通用面板 `ui-frame-panel-9slice` | 四角 32px / 四边 24px | 用于背包、技能、图鉴、存档面板 |
| 槽位 `ui-frame-slot-9slice` | 固定 48×48 | 物品格；选中态加 1px 灵光青描边 |
| 卡带面板 `ui-frame-save-9slice` | 四角 32px | 存档槽专用，右上角留"指示灯"小方孔 |

- 九宫格拉伸**只允许整数倍或按边平铺**，禁止自由缩放（会把边框拉成非整数像素）。
- 面板内边距统一 `16px`，面板间距 `12px`。

### 8.3 血条 / 灵力条 / 心境条

| 条 | 底槽 | 填充 | 特殊 |
|---|---|---|---|
| 生命 `ui-bar-hp` | 深墨青 `#0d1f27` | 血色 `#8f2b2b` → 亮血色（衍生 +15% 明度） | `< 30%` 时条体以 2Hz 脉冲 |
| 灵力 `ui-bar-mp` | 深墨青 | 灵光青 `#4fd1c5` → 暗灵光（衍生 −15%） | 灵力不足时按钮置灰并闪条 |
| 心境 `ui-bar-mind` | 深墨青 | 符纸黄 `#e0c070` | `< 30` 时条体边缘泛血色 |
| 修为 `ui-bar-exp` | 深墨青 | 月白 `#e8e6dc` | 满值时整条呼吸发光（两帧交替） |

- 条体高 8px（HUD）/ 12px（战斗界面），外框 1px 深墨青。
- **不用渐变色条**，只用两段硬色块 + 1px 高光行，保持像素感。

### 8.4 图标风格

1. 统一 32×32，**1px 深墨青描边**，透明背景，图形占满 28×28 内容区。
2. 光源统一自**左上 45°**；所有图标共用同一明暗层次（亮面 / 中间色 / 暗面 三阶）。
3. 品质用**外框色**表达，不改图标本体：凡品灰白 `#6b7570`、良品苔绿、珍品夜蓝、灵品血色、神品符纸黄、仙品月白（对应 [11-数据表规范](11-数据表规范.md) §3.1 的稀有度）。
4. 图标不得含文字、不得含数字。

### 8.5 按钮三态

| 状态 | 表现 |
|---|---|
| 常态 | 暗青底 + 古铜 1px 边 + 月白文字 |
| 悬停 | 整体明度 `+12%`；古铜边换成符纸黄 |
| 按下 | 整体明度 `−10%`，内容整体下移 `2px`，边宽 2px |
| 禁用 | 去饱和 60% + `alpha 0.5`，不响应悬停 |

- 焦点（键盘操作）：在古铜边外再加 1px 灵光青描边，保证手柄/键盘可见。
- 按钮音：悬停可选（默认关）、点击 `sfx-ui-click`、确认 `sfx-ui-confirm`、取消 `sfx-ui-cancel`。

### 8.6 分辨率与缩放策略

| 项 | 方案 |
|---|---|
| 逻辑分辨率 | **640×360**（16:9），所有 UI 按此尺寸布局 |
| 缩放 | **整数倍缩放**：`1×`(640×360) / `2×`(1280×720) / `3×`(1920×1080) / `4×`(2560×1440)；取当前窗口能容纳的最大整数倍 |
| 非整数窗口 | 留黑边（letterbox）居中，**绝不使用 1.5× 这类非整数缩放** |
| Phaser 配置 | `pixelArt: true`、`roundPixels: true`、`antialias: false`、`scale.mode: Phaser.Scale.FIT` + `autoCenter: CENTER_BOTH` |
| CSS | 画布 `image-rendering: pixelated`（Safari 加 `-webkit-optimize-contrast`） |
| 大屏适配 | ≥ 1920 宽时可在 `UIScene` 外侧加装饰性古铜边框填满黑边；背景用 `bg-*`（1920×1080） |
| 小屏（手机竖屏） | 提示"横屏游玩体验更好"，仍可玩；UI 面板自动改为全屏抽屉 |
| 文本 | 文本对象 `resolution = 游戏缩放倍数的整数`（1×→1，2×→2），避免文字被系统二次采样 |

## 九、特效与氛围

### 9.1 昼夜 tint 参数

引用 [10-地图与区域规划](10-地图与区域规划.md) §4.1 的四段表现，落地为全局 `tint`（一层覆盖，不做逐光源光照）：

| 视觉段 | 时辰 | 覆盖色 | alpha | 额外层 |
|---|---|---|---|---|
| 晨 | 卯~辰 | `#ffd9a0`（暖橙白） | `0.10` | 无 |
| 昼 | 巳~未 | `#ffffff`（无色） | `0.00` | 无 |
| 暮 | 申~酉 | `#c9713a`（暮橙，§2.2 例外色） | `0.18` | 无 |
| 夜 | 戌~寅 | `#5a6a9a`（对应 [11-数据表规范](11-数据表规范.md) §5.6 的 `night` tint） | `0.45` | 灯火遮罩：在存档点、客栈、商店位置叠 `#e0c070` alpha 0.20 的圆形光斑 |

- 过渡：相邻时段切换用 `1200ms` 线性补间（`SceneTransition` 期间不切换，避免叠加）。
- 夜间必须逐张地图验收"`overhead` 层遮挡正确、`ground` 不糊成一团"（[10-地图与区域规划](10-地图与区域规划.md) §7）。

### 9.2 天气粒子

| 天气 | 粒子贴图 | 数量 | 行为 | 附加 |
|---|---|---|---|---|
| 雨 | `particle-rain`（2×8） | 200 | 下落 `380 px/s`，轻微左偏 | 地面溅点每 400ms 一次；`sfx-rain-ambient` 循环 |
| 雷雨 | 同上 | 260 | 同上 | 每 6~14s 一次全屏白闪 `120ms` + `sfx-thunder-ambient` |
| 雪 | `particle-snow`（3×3） | 140 | 下落 `70 px/s` + 正弦横摆 | 落地淡出，不留痕 |
| 雾 | 4 张大雾贴图（512×256） | 4 层 | 横向缓慢平移 `8 px/s` | alpha `0.25`，视口四角更浓（"视野缩小"） |
| 晴 / 阴 | 无 | 0 | — | 阴天把全局 tint 额外压 `alpha 0.08` 的青灰 |

- 粒子总预算：**任意时刻 ≤ 300 个**；低端设备（帧率持续 `< 45`）自动降到 50%。
- 天气切换在跨日刷新时发生，粒子用 `800ms` 淡入淡出，不做突变。

### 9.3 战斗特效力度分级

| 级别 | 用于 | 帧数 / 尺寸 | 屏震 | 顿帧 | 闪光 |
|---|---|---|---|---|---|
| **L1 轻** | 普攻命中、单体贴符 | ≤ 8 帧 / 64×64 | 无 | 无 | 无 |
| **L2 中** | 常规技能、群体技 | ≤ 16 帧 / 64×64 | `2px / 80ms` | 无 | 轻微 |
| **L3 重** | Boss 技、天劫、突破、神通 | ≤ 32 帧 / 128×128 | `6px / 240ms` | `80ms` | 全屏白闪 `120ms` |
| **L4 演出** | 剧情战阶段切换、结局 | 不限（单独制作） | `8px / 320ms` | `120ms` | 允许色偏 |

### 9.4 屏震与顿帧的使用节制

1. **单场战斗**：屏震累计 ≤ 6 次；同一次屏震结束后至少间隔 `400ms` 才允许下一次。
2. **顿帧**：单场 ≤ 3 次，单次 ≤ `120ms`；顿帧期间**输入与计时全停**（不能出现"顿帧后连招出血"）。
3. **L3 以上特效**：同屏不得同时播放两个（排队），避免闪烁伤害视觉。
4. **可访问性**：设置面板提供「减弱屏幕震动」（屏震幅度 ×0.4，L3 降为 L1 表现）与「减少闪光」（取消全屏白闪，改为描边发光），默认**跟随系统 `prefers-reduced-motion`**。
5. **禁止**：连续屏震（"摇成筛子"）、战斗全程常驻震屏、用屏震掩盖动画帧缺失。

## 十、音频规范

### 10.1 分轨与音量默认值

| 轨 | 默认音量 | 存储 | 说明 |
|---|---|---|---|
| BGM | `0.70` | `ec:settings:v1` 的 `bgmVolume` | 环境与战斗音乐 |
| SFX | `0.80` | `sfxVolume` | 战斗、脚步、交互、环境音 |
| UI | `0.80` | `uiVolume` | 按钮、面板、提示音 |

- 三条独立 `GainNode`，设置面板三个滑块（0~100，步进 5）；主音量不单独做，避免"双重衰减"。
- 切场景时 BGM 交叉淡出/淡入 `800ms`；战斗进入用 `300ms` 加速淡入（要"切入感"）。
- 页面失去焦点自动把 BGM 降到 `0.3`，恢复时回升（避免切标签页时吵人）。

### 10.4 循环点要求

| 类型 | 要求 |
|---|---|
| BGM | **必须无缝循环**：首末采样连续，无静音头尾；优先在 OGG 内嵌 loop 标记 |
| 前奏限制 | 前奏 ≤ 8 秒；战斗 BGM 前奏 ≤ 4 秒（要快速进节奏） |
| 显式循环点 | 若某曲必须指定 `loopStart` / `loopEnd`，需先在 [11-数据表规范](11-数据表规范.md) §5.8 登记 `audio.json` 表结构，再写入配置；**不允许在代码里硬编码秒数**（[13-技术架构与工程约定](13-技术架构与工程约定.md) §8.1） |
| 环境音 | `sfx-rain-ambient`、`sfx-craft-hammer` 等循环音必须末帧与首帧能量一致 |
| 交叉淡化 | 切轨一律 `800ms` 淡化，禁止硬切（环境音除外，允许 `200ms`） |

### 10.5 格式与体积上限

| 类型 | 格式 | 采样率 / 码率 | 体积上限 |
|---|---|---|---|
| BGM | OGG Vorbis 优先，Safari 回退 `.m4a`(AAC) | 44.1kHz / 立体声 128kbps | **≤ 2 MB / 文件** |
| 环境循环音 | OGG Vorbis | 44.1kHz / 单声道 96kbps | ≤ 1 MB |
| 音效 | OGG Vorbis 优先，回退 `.mp3` | 44.1kHz / 单声道 96kbps | ≤ 200 KB / 文件（UI 音 ≤ 50 KB） |

- 全部音频入 `src/assets/audio/`，由 `vite-plugin-pwa` 缓存（[13-技术架构与工程约定](13-技术架构与工程约定.md) §12）。
- **禁止**：未压缩 wav 入库、时长超过 3 分钟的单曲、超过上限还指望"压缩器补救"。

## 十一、授权与合规

### 11.1 AI 生成素材的授权说明

1. **归属**：本作美术与音频中的 AI 生成部分，由项目使用 Retro Diffusion 系列模型（rd-tile / rd-animation / rd-plus / rd-fast）生成，生成物的使用与商用范围以**生成当日的服务条款**为准；每次大批量生成前需复核一次条款，条款变更时的记录写入附录 A.2。
2. **人工创作叠加**：所有 AI 素材均经过 §4.3 的人工后期（取色归一、帧对齐、边缘清理、风格统一），生成物在最终素材中的贡献需在附录 A.2 中如实标注（生成 + 人工后期 / 仅参考未入库）。
3. **禁止入库**：来源不明、条款不允许商用、或无法追溯到具体模型与日期的 AI 素材，一律不入库。
4. **可追溯性**：附录 A.2 必须能回答"这张图是哪天、用哪个模型、什么提示词生成的"。

### 11.2 第三方素材登记要求

任何非本团队原创、非 Retro Diffusion 生成的素材（字体、音效、占位图、图标、Shader）入库前必须在本文件**附录 A.1** 登记以下字段，缺一不可：
