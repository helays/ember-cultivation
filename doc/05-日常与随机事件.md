## 二、每日委托（30 条）

### 2.1 刷新与接取规则

1. **刷新时机**：游戏内日期跨日（子时结束）时，一次性重掷全部已解锁城镇的委托池。每条城镇从 6 条中抽 **3 条**上板（`dq-qy-xx` 同时最多 3 条可接），未抽中的条目次轮仍有机会。
2. **按境界解锁**：`dq-{城镇码}-01/02` 为低序条目，境界序号要求见下表；同一城镇内序数越大，境界要求越高。默认映射：

   | 条目序 | 最低境界（`realm` 序号） | 对应境界 |
   |---|---|---|
   | `-01` `-02` | 1 | 炼气 |
   | `-03` `-04` | 2 | 筑基 |
   | `-05` `-06` | 3 | 金丹 |

3. **可放弃不惩罚**：接取后可在任务日志中「放弃」，状态变为 `abandoned`，**不掉好感、不掉声望、不进冷却**，当日不可再接到同一条；次日恢复。
4. **超时惩罚**：委托带 `timeLimit`（默认 24 游戏时辰，即跨日即过期）。**过期未完成**才触发惩罚：发布者好感 `-3`、所属势力声望 `-2`、该条进入 **3 日冷却**。
5. **声望惩罚（驱邪悬赏类专属）**：`dq-qy-06` 与 `dq-qq-01` 属于「悬赏·驱邪」类（区域码语义对应 `bw`），若**接受后放弃**，`fac-court` 声望 `-5`；`dq-qq-01` 放弃则 `fac-yao` 声望 `-5`。此类任务在任务日志中以红色「悬赏」标签区分，接取前二次确认。
6. **重复接取**：全部 30 条 `repeatable: true`，但同一条在**同一日内只能完成一次**（完成后写入 `flag-num-dq-{id}-day` 记录日号）。
7. **奖励基准**：`common` 档 = 修为 `60~120` + 灵石 `20~60`；`fine` 档 = 修为 `120~220` + 灵石 `60~120` + 1 件消耗品。具体数值以 [16-数值设计](16-数值设计.md) 的委托基线表为准，本表只写"奖励要点"。

## 三、季节事件（16 条）

### 3.1 季节专属灵草与灵田联动

季节事件的核心是**与灵田系统互锁**：季节事件提供专属种子，灵田产出又反过来解锁季节事件的后续分支。

| 季节 | 专属灵草 | 物品 ID | 生长时辰 | 灵田联动效果 |
|---|---|---|---|---|
| 春 | 春兰草 | `item-mat-seed-chunlan` | 12 | 春季播种生长速度 ×1.2；收获后 3 日内采集类委托奖励 +10% |
| 春 | 醒魂芽 | `item-mat-seed-xinghun` | 18 | 收获后心境 +5，可作驱邪符替代材料 |
| 夏 | 赤阳花 | `item-mat-seed-chiyang` | 10 | 夏季生长速度 ×1.1；炼丹时火候容错 +1 档 |
| 夏 | 萤心草 | `item-mat-seed-yingxin` | 8 | 夜间收获额外产出 1 份；可作为洞府照明材料 |
| 秋 | 月桂叶 | `item-mat-seed-yuegui` | 20 | 秋分收获品质提升一档；炼丹成功率 +5%（当月） |
| 秋 | 金穗子 | `item-mat-seed-jinsui` | 16 | 收获灵石附带量 +20%；可炼制回气丹 |
| 冬 | 霜心芝 | `item-mat-seed-shuangxin` | 24 | 冬季生长速度 ×0.8，但产出的丹药可保存心境加成 |
| 冬 | 冰髓藻 | `item-mat-seed-bingsui` | 20 | 需在寒潭边灵田格种植，收获后免疫一次"心魔夜" |

**通用规则**：

1. 季节灵草种子**只在该季节的 `eq-*` 事件中产出**，非当季不可种植（除洞府"地脉暖棚"二级升级后可跨季 1 种，见 `homestead.json`）。
2. 每个季节事件完成后写入 `flag-season-{season}-{序}` 布尔标记，用于季节切换时结算"未参加的季节事件"（无惩罚，只是错过）。
3. 灵田收获时若当前季节与作物季节不符，产出减半并弹提示"此物不合天时"。

## 七、宗门周期任务（30 条）

### 7.1 周刷新规则

1. **刷新周期**：每 **7 游戏日**（跨周）重置一次；重置时未完成的宗门任务自动失效，**不扣声望**（与每日委托的过期惩罚不同）。
2. **可接数量**：每个势力每周上板 **3 条**（从 5 条中抽 3），玩家**每周最多完成 2 条同势力任务**（防止刷声望）。
3. **入门门槛**：势力声望 `< 25` 时该势力任务锁定，面板显示"尚未入门"。
4. **奖励基准**：势力声望 `+3~+6`、修为 `200~600`、灵石 `60~200`，另给该势力特产材料或配方残页。
5. **互斥提示**：完成 `fac-kunlun` 的周常会按 [01-世界观与设定](01-世界观与设定.md) §4.1 对 `fac-jiejiao` 施加 `-5`（反向亦然）；任务面板在接取前显示该副作用。
6. **计数核对**：6 个势力 × 5 条 = **30 条**（`fq-kl-*` / `fq-ms-*` / `fq-jc-*` / `fq-qq-*` / `fq-jj-*` / `fq-mf-*`）。`fq-` 是**宗门周期任务专用前缀**，与 `sq-` 的一次性支线严格区分；势力码表见 [11-数据表规范](11-数据表规范.md) §2.3。

## 八、触发与权重实现约定

> 本节是 `events.json` / `quests.json` 中**周期与随机内容**的字段写法约定。字段名与取值必须来自 [11-数据表规范](11-数据表规范.md) §3.2（`effects` 白名单）、§3.3（`conditions` 白名单）、§3.4（任务状态枚举）与 §4（任务表结构）。**任何未登记的 `type` 一律视为配置错误。**

### 8.1 `trigger` 字段的扩展写法

标准任务表（[11-数据表规范](11-数据表规范.md) §4）的 `trigger` 已含 `mode` / `map` / `timeOfDay` / `conditions` / `chance` / `once`。周期与随机内容在其上追加三个**已登记于本文档的扩展字段**（同时需回填至 `11-数据表规范` §4 的字段表）：

| 字段 | 类型 | 含义 | 取值范围 |
|---|---|---|---|
| `cooldown` | number | 触发后的冷却，单位**游戏日** | `0`~`90`；`0` 表示无冷却 |
| `weight` | number | 池内基础权重 | `1`~`100`，与 `level` 稀有度基准相乘 |
| `pool` | string | 所属事件池 ID | `pool-wild-*` / `pool-mf-*` / `pool-season-*` |
| `priority` | number | 同帧多事件竞争时的优先级 | `0`~`10`，默认 `0`；剧情演出用 `10` |

### 8.2 权重抽样算法

```
候选 = 全部满足 conditions 且未在冷却中且未触发过 once 的事件
权重(event) = event.weight × rarityBase[event.level] × depthMod[当前深度]
rarityBase = { common: 60, rare: 30, legend: 10 }        // §5.1
depthMod   = 1 + 0.05 × max(0, 深度 - 1)                  // 仅秘境生效，上限 +0.40
抽取：按权重轮盘，一次抽取只触发 1 条（剧情 priority = 10 者优先插队且不占配额）
```

- **深度**定义：`map-mf-dingong` 取当前层数；固定秘境取 `0`（即 `depthMod = 1`）。
- **单次进图配额**：秘境事件计数写入 `flag-num-mf-event-count`，达到 3 后本次进图不再抽取；离开秘境时清零。
- **权重重掷时机**：仅在地图切换或进入战斗返回后重掷，**不随每秒移动重掷**（避免"走一步刷一次"）。

### 8.3 `chance` 与 `once` 的写法

| 字段 | 写法 | 说明 |
|---|---|---|
| `chance` | `0.0 ~ 1.0` 的浮点小数，**不写百分数** | `chance: 0.3` 即 30%。`chance: 1` 时**不掷骰**，直接通过（见 [02-核心玩法系统](02-核心玩法系统.md) §8.3 第 4 步） |
| `once` | 布尔 | `true` 表示全局只触发一次，触发后写入 `worldFlags[事件ID] = true`；`false` 表示可重复，重复性由 `cooldown` 控制 |
| `cooldown` | 整数（游戏日） | 触发时写入 `flag-num-cd-{事件ID}` = 当前日号；判定时比较 `当前日号 - flag-num-cd-{事件ID} >= cooldown` |
| `repeatable` | 布尔（任务表字段） | 每日委托与宗门周常恒为 `true`；季节事件为 `true`（每季一次由季节条件天然限制） |

> **`once` 与 `cooldown` 互斥使用**：一条事件要么 `once: true`（一次性剧情），要么 `once: false` + `cooldown > 0`（可重复但需冷却）。二者同时为 `true`/`>0` 时以 `once` 优先，校验器报 `WARN`。

### 8.4 冷却与去重规则

1. **冷却存储**：全部冷却以**数值世界标记**形式落盘，命名 `flag-num-cd-{事件ID}`（符合 [11-数据表规范](11-数据表规范.md) §6 第 2 条"数值标记以 `flag-num-` 开头"）。
2. **同图去重**：同一地图内，**同类事件**（同 `pool` 且同 `level`）在连续两次触发间必须间隔 **≥ 3 次地图切换**；跨图后重新计数。
3. **全局传说去重**：`legend` 档事件在**同一周目内全局唯一**，`once` 恒为 `true`；触发后写入 `flag-legend-{事件ID}`，池中永久移除该条。
4. **任务互斥**：`conflicts` 字段用于道侣线与同伴线（见 [04-支线任务](04-支线任务.md)）；周期内容中只有 `dq-qy-06` 与 `dq-ms-04` 互斥（同一日不可同时接取"清理坟头"与"超度孤魂"，语义冲突）。
5. **NPC 忙碌去重**：同一 NPC 发布的委托与其对话任务不可同时进行；接取时校验 `giver` 是否已有进行中的任务，有则面板置灰。

### 8.5 保底规则

| 保底项 | 规则 | 状态存储 |
|---|---|---|
| 稀有事件保底 | 连续 **5 次**触发的均为 `common` 时，第 6 次抽取**强制命中 `rare`** 档 | `flag-num-luck-common-streak` |
| 传说事件保底 | 连续 **30 次**抽取未命中 `legend` 时，第 31 次抽取的 `legend` 权重 ×3（不强制，仅提权） | `flag-num-luck-legend-drought` |
| 每日委托保底 | 某城镇当日上板 3 条中，**至少 1 条**的 `realm` 要求低于玩家当前境界（保证可做） | `flag-num-dq-floor-{城镇码}` |
| 秘境宝箱保底 | 程序化地宫必生成 1 个宝箱房、1 个精英房、1 个 Boss 房（见 [10-地图与区域规划](10-地图与区域规划.md) §6） | 地宫种子（写档，不重掷） |
| 无战斗保底 | 玩家心境 `< 30` 时，随机池中**带战斗的事件权重 ×0.5** | 运行时计算，不入档 |
