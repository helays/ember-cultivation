## 一、总览与两条铁则

### 1.1 两条铁则

1. **先跑通最小可玩循环**：`移动 → 遇敌 → 战斗 → 获得修为 → 存档`。M1~M4 **严格围绕这条循环推进**，每一阶段都必须让这条循环比上一阶段更完整；M4 结束时循环必须端到端可用，不许有任何一环是假的。
2. **存档先做**：在 **M1 就落地基础 IndexedDB 存档**（三槽位读写 + 自动备份槽位骨架），而不是等到 M4。理由见 [13-技术架构与工程约定](13-技术架构与工程约定.md) ADR-004：存档结构一旦被四个阶段的数据结构反复改动，后期重构成本会指数上升。**任何阶段新增的持久化字段，都必须当周写进 [12-存档与时间系统](12-存档与时间系统.md) 并补迁移函数。**

### 1.2 最小可玩循环的落地分配

| 循环环节 | 落地阶段 | 用到的关键模块 |
|---|---|---|
| 移动（自由移动 + 碰撞 + 摄像机） | **M1** | `src/phaser/systems/MovementSystem.js`、`src/phaser/entities/Player.js`、`src/phaser/systems/MapLoader.js` |
| 存档（三槽位 + 写入动画） | **M1**（基础）/ **M4**（全字段 + 迁移 + 恢复） | `src/core/saveManager.js`、`src/vue/components/SavePanel.vue`、`src/vue/stores/saveStore.js` |
| 遇敌（距离检测触发） | **M1**（占位触发）/ **M3**（真正进入战斗） | `src/phaser/systems/EncounterSystem.js` |
| 战斗（回合制 + 伤害 + AI） | **M3** | `src/phaser/scenes/BattleScene.js`、`src/phaser/battle/{TurnManager,DamageCalc,EnemyAI,BattleState}.js` |
| 获得修为（奖励结算 + 修炼） | **M3**（战斗奖励）/ **M4**（打坐与突破） | `src/core/effectRunner.js`、`src/vue/stores/playerStore.js` |
| 循环加固（配置表校验 + 事件 + 任务） | **M4** | `src/core/{registry,validate,conditionChecker}.js` |

## 三、里程碑验收标准

每条都必须**可客观验证**，不允许"看起来差不多了"。

### M0 · 工程初始化

1. `pnpm dev` 启动后浏览器出现 640×360 的逻辑画布，`pixelArt` 生效（放大 800% 无抗锯齿灰边）。
2. `pnpm build` 与 `pnpm preview` 均成功，产物可正常启动。
3. `src/core/bus.js` 的 `EVT` 常量与 [13-技术架构与工程约定](13-技术架构与工程约定.md) §3.2 的表格**逐条一致**（脚本比对，无遗漏无多余）。
4. 全仓库搜索 `import`，`src/phaser/` 与 `src/vue/` 之间**零直接引用**。
5. `git status` 中不出现 `runtime/` 下任何文件。

### M1 · 移动原型 + 基础存档

1. 玩家可在一张 Tiled 地图上自由移动且**无法穿墙**：以调试模式沿墙走满一圈，无卡缝、无穿越。
2. `collision` 层的三类对象均可被引擎识别：`wall` 阻挡、`water` 减速、`trigger` 触发且不阻挡。
3. 三槽位各存一次档后**重开浏览器**，三个槽位的 `saveName` / 境界 / 游玩时长与写入时一致。
4. 覆盖已有槽位时必定弹出二次确认，且默认焦点在「取消」。
5. 写入动画从点击到显示"存档完成"**不短于 1200ms**；写入中断（手动杀标签页）后重启会提示回滚。
6. 两个标签页同时存档，不出现"槽位变空"或"内容错乱"（`rev` 冲突提示按 [12-存档与时间系统](12-存档与时间系统.md) §1.4 出现）。

### M2 · 卡带机素材生产线

1. `node scripts/check-assets.mjs` **全绿**（退出码 0；聚合入口 `node scripts/build-assets.mjs --check` 同口径）：调色板一致、尺寸精确、命名合规、清单双向一致、瓦片接缝、音频规格、授权字段非空。

## 四、依赖关键路径与降级方案

### 4.1 关键路径

```
M0 目录骨架与事件总线
      └─▶ M1 saveManager 三槽位读写 ──▶ M4 存档全字段 + 迁移 + 恢复 ──▶ M6 存档兼容回归
      │                                        ▲
      └─▶ M1 地图对象层 + 移动 ──▶ M3 战斗核心 ─┘
                                       ▲
                     M4 registry + validate（配置表校验器）
                                       │
                       M5 全部内容依赖"校验器 + 战斗核心 + 存档"三者齐备
```

**三个必然阻塞后续工作的任务**：

| 关键任务 | 阻塞什么 | 若延期 |
|---|---|---|
| `src/core/saveManager.js`（M1） | M4 的字段扩充、M5 的周目与图鉴、M6 的兼容回归全部排队 | **不可砍**：可砍"写入动画与并发检测"，但三槽位读写必须当晚于 M1 结束前落地 |
| `src/core/validate.js` 配置表校验器（M4） | 全部内容生产（没有校验器，90 条主线 + 104 条支线的错引用会变成无底洞） | **不可砍**：先从 10 项校验降到 5 项核心（引用完整性、白名单、`flags` 一致、`prereq` 无环、JSON 可解析），其余延后 |
| `src/phaser/battle/{DamageCalc,TurnManager}.js`（M3） | M5 的敌人与技能数值、M6 的平衡 | **不可砍核心**：可砍 Boss 多阶段演出与心魔战，保留单体回合制 |

### 4.2 降级方案（若延期先砍什么）

按"砍掉后玩家仍能完整通关"的顺序从下往上砍：

| 优先级 | 可降级项 | 降级方案 |

**美术与音频产能（按"产出条数/周"计量，不按"AI 批量生成张数"估算）**

口径：**1 条 = 1 个通过校验并登记进 `assets.manifest.json` 的素材**；一整套角色动作（多帧）算 1 条。

| 产出类型 | 每周产出 | 前置条件 |
|---|---|---|
| `.px.txt` 矩阵：图标 / 粒子 / 小物件 | 6~10 条 | 已有同类模板，尺寸小、用色少 |
| `.px.txt` 矩阵：一整套角色动作（含帧对齐与脚底线校正） | 1 套 | 需先在 `AssetPreviewScene` 的 B 区跑通对齐检查 |
| L0 程序化瓦片集 | 1 张 | 改 `scripts/gen-tiles.mjs` 的图案函数，同类地貌可复用 |
| `.psg.txt` 音序：BGM | 0.5 条（2 周 1 条） | 需先跑通无缝循环点（[14-美术与音频规范](14-美术与音频规范.md) §10.4） |
| `.psg.txt` 音序：SFX | 3 条 | 短音，可批量调参 |

- 每周是否达标以 `node scripts/check-assets.mjs` 是否全绿为准：**不通过不算产出**（与主线 / 支线"内容完成度"同一口径）。
- 音序产出脚本（`scripts/gen-audio.mjs`）跑通之前，音频条数按 0 计，音频缺口按 §4.2 优先级 3 处理。

**结论与执行方式**：

- M5 的 8 周只交付**内容基线**：一章 + 二章全部 + 三章主体（约 48 条主线 + 50 条支线 + 8 张地图 + 全部系统所需敌人/丹药/法宝/技能最小集）。
- 主线剩余 42 条、支线剩余 54 条、随机事件全部尾巴以**内容冲刺**形式与 M6 打磨**并行**推进；冲刺期保持每周 3 主线 + 6 支线 + 5 事件的节奏。
- 随机事件按"每张地图 20 条起步、上线后按地图逐步加到 30~50 条"滚动加深，**不作为发布阻断项**。
- 美术与音频按上表的"条数/周"滚动补齐；M2 的素材最小集（§3 M2）是进入 M5 的前置——未达标时地图与 UI 只能继续挂占位素材，**不允许**以"先发内容、素材后补"的方式越过。
- 每两周做一次"内容完成度 vs 排期"复核；若连续两次未达标，按 §4.2 顺序降级。
