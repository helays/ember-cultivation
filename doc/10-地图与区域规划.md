## 二、Tiled 图层约定

每张地图的图层**顺序与命名固定**，Phaser 按名称读取，不按索引：

| 图层名 | 类型 | 说明 |
|---|---|---|
| `ground` | 瓦片层 | 地面，必须铺满 |
| `detail` | 瓦片层 | 细节装饰（草、裂缝、血迹） |
| `building` | 瓦片层 | 建筑、树木、岩石（有体积感的部分） |
| `overhead` | 瓦片层 | 覆盖在角色之上的部分（屋檐、树冠），渲染顺序最高 |
| `collision` | 对象层 | 碰撞体，`wall` / `water` / `trigger` |
| `interact` | 对象层 | 可交互物：NPC 锚点、采集点、商店、存档点、可开关 |
| `spawn` | 对象层 | 出生点与传送落点，含 `from` 属性标识来源传送点 |
| `event` | 对象层 | 事件点，含 `eventId` 指向 `events.json` |
| `encounter` | 对象层 | 遇敌区域（多边形），含 `encounterTable` 引用遭遇表 |
| `deco` | 对象层 | 纯装饰（无碰撞），用于氛围物件 |

> `spawn` 与 `interact` 必须在 `collision` 之后绘制，便于 Tiled 中可视编辑。

> **瓦片层 JSON 必须带 `opacity: 1`（与 `visible: true`）**。Phaser 解析 Tiled JSON 时按
> `group.opacity × layer.opacity` 计算图层透明度，字段缺失时得到 `1 × undefined = NaN`，
> 表现为整层瓦片完全透明、画面只剩角色（渲染计数照常，控制台无报错）。Tiled 导出总是
> 写入该字段；手写/脚本生成的地图（`runtime/tools/gen-*.mjs`）必须同样写入。

**瓦片集与 TSX 的硬约束**：

1. 瓦片集 PNG **必须是 PNG-8 索引色**（`colorType = 3`），且调色板**严格等于**固定索引板——真源是 [`src/assets/palette.json`](../src/assets/palette.json)，[14-美术与音频规范](14-美术与音频规范.md) §2.1 为校验副本。不接受 24/32 位真彩，不允许任何色板外颜色。
2. TSX 的 `image` 指向的 PNG **必须已在 [`src/assets/assets.manifest.json`](../src/assets/assets.manifest.json) 登记，且该条目的 `kind` 为 `tile`**（清单字段见 [11-数据表规范](11-数据表规范.md) §5.9）；未登记的瓦片集不得被地图引用。
3. `collision` 层是**对象层**，与索引色无关：碰撞体只描述体积（`wall` / `water` / `trigger`），既不参与取色，也不写进任何瓦片集 PNG。

**规则**：

1. 传送需成对存在 `A.spawn` ↔ `B.spawn`，`from` 属性互指。
2. 未解锁区域的传送点显示为"雾墙"，交互给出提示文本。
3. 洞府传送阵在二章解锁后可从任意城镇客栈传送回洞府（单向免费，返回有费用）。
4. 战斗结束后玩家回到所在地图的原位置（保存 `position`）。

## 四、昼夜与天气

### 4.1 昼夜表现

| 时段 | 时辰 | 表现 | 玩法影响 |
|---|---|---|---|
| 晨 | 卯~辰 | 暖色调，鸟鸣 | 灵草可采、NPC 上工 |
| 昼 | 巳~未 | 正常色 | 常规任务、集市开放 |
| 暮 | 申~酉 | 橙红渐变 | 部分 NPC 归家、夜市未开 |
| 夜 | 戌~寅 | 暗蓝 + 灯火，色调切换 | 妖鬼增强 +20%，僵尸出现，鬼市开放 |

全局用一层 `tint` 覆盖 + 灯光遮罩实现，不做逐光源光照系统（预算控制）。

### 4.2 天气

| 天气 | 出现权重 | 效果 |
|---|---|---|
| 晴 | 45% | 无 |
| 阴 | 20% | 遇敌率 ×1.1 |
| 雨 | 15% | 火系伤害 ×0.9，水系 ×1.1，驱邪符效果 ×0.8 |
| 雷雨 | 8% | 雷系 ×1.2，野外遇敌率 ×1.3，可能触发"雷击机缘" |
| 雾 | 8% | 视野缩小（视口加雾层），鬼魂类遇敌率 ×1.4 |
| 雪（冬） | 4% | 移动速度 ×0.9，冰系 ×1.1 |
| 血月（事件） | 剧情 | 妖鬼全属性 ×1.5，仅月圆之夜主线触发 |

天气按日刷新（写入存档，读档不重掷），可在客栈"等天气"消耗时辰重掷。

## 五、事件点密度与分布原则

| 地图类型 | 事件点/千格 | 主线占比 | 支线占比 | 随机占比 |
|---|---|---|---|---|
| 城镇 | 4~6 | 30% | 50% | 20% |
| 野外 | 2~4 | 15% | 25% | 60% |
| 宗门 | 4~7 | 35% | 50% | 15% |
| 秘境 | 3~5 | 20% | 20% | 60% |

**分布原则**：

1. 每个城镇至少 1 个**存档点**、1 个**商店**、1 个**任务发布板**。
2. 主线必经之路上不得放置会打断节奏的随机事件（`chance` 为 1 的除外）。
3. 隐秘事件点（如残碑、暗格）需**偏离主路 5 秒以上步程**，鼓励探索。
4. 连续同类事件点间距 ≥ 8 格，避免密集轰炸。

## 六、随机化模块（`map-mf-dingong`）

噬灵地宫是唯一的程序化地图，用于验证"模块拼接"方案：

- **模块库**：在 Tiled 中预做 6 种房间 + 4 种走廊模块（各含 9 个出入口锚点），导出为独立 JSON。
- **生成算法**：随机游走生长 + 连通性校验 + 死路回填，保证**必定连通且存在出口**。
- **难度缩放**：房间数 = `4 + 境界序号`，上限 12；敌人强度随房间深度递增。
- **保底设计**：每层必定生成 1 个宝箱房、1 个精英房、1 个 Boss 房（最深处）。
- **种子**：种子写入存档，读档后地宫布局不变（避免读档刷图）。
- **实现预算**：此项列为**可选增强**，若排期紧张可降级为固定 3 种手工布局随机抽一。

## 七、地图验收清单

每张地图完成时需逐项确认：

- [ ] 四个瓦片层（`ground`/`detail`/`building`/`overhead`）与五个必填对象层（`collision`/`interact`/`spawn`/`event`/`encounter`，`deco` 可选）齐全且命名正确
- [ ] 碰撞体不留缝隙（可用调试模式走边一圈验证）
- [ ] `spawn` 点数量与对端传送点一一对应
- [ ] `event` 层的 `eventId` 全部存在于 `events.json`
- [ ] `encounter` 层引用的遭遇表存在，且敌人等级与地图解锁章节匹配
- [ ] 玩家可从任意可站立点走到任意事件点（连通性检查）
- [ ] 昼夜 tint 下不缺图（`overhead` 层在夜间的遮挡正确）
- [ ] 事件点密度符合 §5 原则
- [ ] 地图 JSON 与 TSX 瓦片集路径有效
