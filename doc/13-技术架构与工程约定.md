### 2.1 分层依赖规则

```
vue/components ──▶ vue/stores ──▶ core ──▶ data/*.json
phaser/scenes  ──▶ phaser/entities ──▶ phaser/systems ──▶ core ──▶ data/*.json
                          │
                          └── 禁止：phaser/ 直接 import vue/，vue/ 直接 import phaser/
```

- `core/` 是**唯一的规则中枢**，不依赖 Phaser 也不依赖 Vue（可在 Node 中单测）。
- `vue/` 与 `phaser/` **只通过 `core/bus.js` 通信**，禁止互相 `import`。

## 三、Phaser ↔ Vue 通信协议

### 3.1 事件总线

`core/bus.js` 导出一个 `mitt` 风格的事件总线。**所有跨层通信必须走它**，事件名使用 `域:动作` 命名。

```js
// core/bus.js
import mitt from 'mitt'
export const bus = mitt()
// 事件名常量集中定义，禁止散落字符串字面量
export const EVT = {
  GAME_START: 'game:start',
  DIALOG_OPEN: 'dialog:open',
  DIALOG_CHOICE: 'dialog:choice',
  DIALOG_CLOSE: 'dialog:close',
  MENU_TOGGLE: 'menu:toggle',
  BATTLE_START: 'battle:start',
  BATTLE_SUMMON: 'battle:summon',
  BATTLE_COMMAND: 'battle:command',
  BATTLE_TURN: 'battle:turn',
  BATTLE_END: 'battle:end',
  STAT_CHANGED: 'stat:changed',
  ITEM_GAINED: 'item:gained',
  QUEST_UPDATED: 'quest:updated',
  SAVE_REQUEST: 'save:request',
  SAVE_WRITTEN: 'save:written',
  TOAST: 'ui:toast',
  EVENT_PROBE: 'event:probe',
  SCENE_TRANSITION: 'world:transition',
}
```

### 3.2 事件清单

| 事件名 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `game:start` | Vue → Phaser | `{ mode: 'new'\|'continue'\|'load', slot?, state: { location, position, time } }` | 会话引导：主菜单确认后携带初始状态启动 `WorldScene`（doc/12 §5.2） |
| `dialog:open` | Phaser → Vue | `{ npcId, nodeId, text, choices[] }` | 打开对话框 |
| `dialog:choice` | Vue → Phaser | `{ nodeId, choiceIndex }` | 玩家选择 |
| `dialog:close` | 双向 | `{ npcId }` | 关闭对话框 |
| `menu:toggle` | 双向 | `{ menu: 'inventory'\|'skills'\|'quests'\|'save'\|'codex' }` | 开关面板（打开时暂停世界） |
| `battle:start` | Phaser → Vue | `{ enemies[], allies[], bgm }` | 进入战斗，显示战斗 UI |
| `battle:summon` | Vue → Phaser | `{ enemies[], reason }` | 菜单/剧情侧发起战斗（心魔、事件战），Phaser 冻结世界并启动 `BattleScene` |
| `battle:command` | Vue → Phaser | `{ actorId, command, targetId?, skillId? }` | 玩家下达指令 |
| `battle:turn` | Phaser → Vue | `{ order[], log[], active?, round?, units? }` | 回合推进，刷新 UI（`active` 为当前行动者、`round` 为回合数、`units` 为双方单位血量快照，玩家回合等待 `battle:command`） |
| `battle:end` | Phaser → Vue | `{ result: 'win'\|'lose'\|'flee', rewards }` | 战斗结束 |
| `stat:changed` | Phaser → Vue | `{ hp, mp, mind, realm, stage }` | 属性变化，刷新 HUD |
| `item:gained` | Phaser → Vue | `{ itemId, qty }` | 物品获得提示 |
| `quest:updated` | Phaser → Vue | `{ questId, state, step }` | 任务日志刷新 |
| `save:request` | Vue → Phaser | `{ slot }` | 请求存档（Phaser 先冻结世界） |
| `save:written` | Phaser → Vue | `{ slot, ok }` | 存档完成，播放写入动画 |
| `ui:toast` | 双向 | `{ text, level }` | 轻提示 |
| `event:probe` | Phaser → Vue | `{ eventId }` | 场景探得事件点，五步解析（once→条件→chance→写 flag→冷却，doc/02 §8.3）由 Vue 侧执行 |
| `world:transition` | Phaser → Vue | `{ from, to, fade }` | 场景切换遮罩 |

**同时只允许一个阻塞式 UI**：对话框与菜单互斥，通过 `uiStore.blocking` 状态位管理。

## 四、Pinia store 划分

| store | 职责 | 关键 state |
|---|---|---|
| `playerStore` | 角色属性、境界、灵根、心境 | `name` `realm` `stage` `exp` `hp/maxHp` `mp/maxMp` `attrs` `mind` |
| `inventoryStore` | 背包、装备、快捷栏 | `items[]` `capacity` `equipment` `hotbar[4]` |
| `questStore` | 任务进度、世界标记 | `questProgress{}` `worldFlags{}` `active[]` |
| `worldStore` | 位置、时间、天气、解锁 | `location` `position` `time{}` `weather` `unlockedLocations[]` |
| `uiStore` | UI 状态机 | `blocking` `openMenu` `dialog` `toasts[]` |
| `saveStore` | 存档槽、读写状态 | `slots[3]` `autoBackup` `writing` |

**规则**：store 只保存状态，不含业务流程；业务流程写在 `core/` 的纯函数中，由 store 调用。

## 五、数据加载与校验

1. `core/registry.js` 在 `BootScene` 中一次性加载所有 JSON，构建 `Map<id, entry>` 索引。
2. 加载后执行**引用完整性检查**（开发模式下 `console.error` 汇总报告）：
   - 跨表引用是否存在
   - `effects`/`conditions` 的 `type` 是否在白名单
   - 任务 `prereq` 图是否有环
   - `flag-*` 是否在登记表中
3. 生产构建时校验失败 → 抛错阻断构建（避免带着坏数据上线）。
4. 校验器本身的实现放 `src/core/validate.js`，其**独立运行脚本**放 `runtime/tools/`。
5. **素材与配置表各一道门禁，互不替代**：
   - **素材合法性**（调色板一致 / 尺寸精确 / 命名合规 / 清单双向一致 / 瓦片接缝 / 音频规格 / 授权字段非空 / 帧对齐）由 `node scripts/check-assets.mjs` 把关；**聚合入口**是 `node scripts/build-assets.mjs --check`——按依赖顺序跑各生成器的 `--check`（不写盘），最后调用校验器（见 §7.1）；
   - **配置表合法性**（跨表引用 / `effects`·`conditions` 白名单 / `prereq` 无环 / `flag-*` 登记）由 `src/core/validate.js`（运行时与构建期）与 `runtime/tools/validate.js`（本地独立运行入口）把关。

## 六、状态与存档的边界

- 所有**需要持久化**的状态必须能从 store 序列化进存档结构（见 [12-存档与时间系统](12-存档与时间系统.md)）。
- store 中不得保存 Phaser 对象引用（Sprite、Tween、物理体）——这是最常见的存档污染源。
- 场景重建时从 store 恢复，而不是从 Phaser 残留状态恢复。

## 七、`scripts/` 与 `runtime/` 的边界 ❗

### 7.1 `scripts/`：入库的生产线

`scripts/` 是**入库、长期维护、被 CI 依赖**的脚本目录，存放素材生产线与构建门禁：

| 脚本 | 职责 |
|---|---|
| `scripts/build-assets.mjs` | **生产线总入口**：按依赖顺序（色板 → L0 瓦片 / UI / 图标 → L1 像素 → L2 音序）重建全部素材并校验；`--check` 为 CI 模式（不写盘，改用各脚本的 `--check`），尚未落地的生成器自动跳过并提示 |
| `scripts/gen-palette.mjs` | 从 `src/assets/palette.json` 生成 `src/core/constants.js` 的 `PALETTE` / `COLOR`，并校验 [14-美术与音频规范](14-美术与音频规范.md) §2.1 的色板表（`--check` 供 CI 用） |
| `scripts/gen-tiles.mjs` | L0：程序化生成瓦片集（构造性无缝，幂等） |
| `scripts/render-pixels.mjs` | L1：`.px.txt` 像素矩阵 → PNG-8，并按 `.atlas.json` 自动拼图集（`--check` 供 CI 用） |
| `scripts/inspect-png.mjs` | 单个 PNG 的元数据 / 调色板合规 / 索引分布 / 接缝指标与 ASCII 预览（人工复核用） |
| `scripts/check-assets.mjs` | **素材全量校验入口**（见 §5 第 5 条），CI 门禁；`--report` 输出 `runtime/reports/assets-check.md` |
| `scripts/lib/png.mjs`、`scripts/lib/pixels.mjs`、`scripts/lib/artkit.mjs` | PNG 编解码、像素矩阵解析与 L0 生成公共设施（色板语义常量、Bayer 抖动、确定性哈希、接缝指标）的唯一实现 |

约定：一律 `.mjs`；**零第三方依赖**（只用 Node 内置模块），因此仓库尚无 `package.json` 时也能直接 `node scripts/xxx.mjs` 运行；脚本幂等——同一输入产出同一字节。

### 7.2 `runtime/`：临时产物与报告（不入库）

**`runtime/` 是所有临时文件、测试工具、调试产物的存放目录，整体被 `.gitignore` 忽略，永不提交。**

| 子目录 | 用途 | 生命周期 |
|---|---|---|
| `runtime/tmp/` | 一次性草稿、导出中间文件、抓取结果 | 随时可删 |
| `runtime/tools/` | **本地**临时 / 实验脚本，以及配置表校验器的本地入口（如 `runtime/tools/validate.js`） | 本地长期保留，不入库 |
| `runtime/reports/` | 脚本输出（校验报告、成长曲线、平衡数据、瓦片平铺预览） | 可删，重跑即得 |
| `runtime/fixtures/` | 测试用存档样本、配置表快照 | 需要时重建 |

**强制规则**：

1. 任何脚本产物、日志、截图、临时 JSON **只能写进 `runtime/`**，不得落在仓库根目录或其他目录。
2. `runtime/` 下的文件**不得被 `src/` 或 `public/` 引用**（否则生产构建会缺文件）。
3. `runtime/` 里的脚本可以 `import` `src/` 的模块（单向依赖），但 `src/` **绝不能** `import runtime/`。
4. **提升规则（已生效）**：需要长期保留、且被 CI 依赖的工具一律**入库到 `scripts/`**，不再放 `runtime/tools/` 等待提升。素材生产线这批脚本（`build-assets` 总入口与 `gen-palette` / `gen-tiles` / `render-pixels` / `inspect-png` / `check-assets` 及 `lib/`）**已经完成提升**——它们长期维护、被 CI 调用、且是素材出图的唯一入口，`runtime/` 里不再保留其副本；规范说明写在本文档，实现直接入库。反之，`runtime/tools/` 只承担**尚未稳定**的本地脚本与配置表校验器的本地入口 `runtime/tools/validate.js`（其规则逻辑仍在 `src/core/validate.js`，见 §5）。

## 八、编码约定

| 项 | 约定 |
|---|---|
| 模块 | ES Module，具名导出优先 |
| 命名 | 文件 `PascalCase.js`（类）/ `camelCase.js`（模块）；变量与函数 `camelCase`；常量 `SCREAMING_SNAKE` |
| 类型 | 用 JSDoc 注释公共函数签名，`jsconfig.json` 开启 `checkJs` 以获得编辑器提示 |
| 缩进/引号 | 2 空格 / 单引号 / 无分号（除非必要） |
| 异步 | 统一 `async/await`，禁止裸 `.then` 链 |
| 错误 | 用户可见错误走 `ui:toast`；开发错误走 `logger.error` 并附上下文 ID |
| 注释 | **解释"为什么"**，不解释"是什么"；引用规范时写 `// 见 doc/11 §3.2` |
| 魔法数字 | 一律来自配置表或 `core/constants.js` |
| 语言 | 代码与注释用英文；面向玩家的文案一律来自 JSON 表，不硬编码中文到代码 |

### 8.1 禁止事项

- ❌ `phaser/` 与 `vue/` 互相 `import`
- ❌ 在代码中硬编码 `item-*` / `enemy-*` / 任务文本
- ❌ 直接操作 IndexedDB 而不经过 `saveManager`
- ❌ 在 store 中保存 Phaser 对象
- ❌ 引入未经登记的 `effects` / `conditions` 类型
- ❌ 把临时文件写到 `runtime/` 之外

## 九、决策记录（ADR）

| 编号 | 决策 | 理由 | 代价 |
|---|---|---|---|
| ADR-001 | 使用 **JavaScript + JSDoc**，不引入 TypeScript | 与 v1.0 设计一致；数据驱动项目主要风险在数据而非类型；降低上手与构建复杂度 | 重构安全性弱于 TS；靠 `checkJs` + 校验脚本弥补 |
| ADR-002 | Phaser 与 Vue **事件总线解耦** | 避免双向耦合导致后期不可维护 | 事件增多需集中登记，否则难追踪 |
| ADR-003 | 配置表用 **JSON 而非 JS 模块** | 可被工具链与外部脚本读取、可被大模型批量生成与校验 | 需要运行时校验兜底 |
| ADR-004 | 存档用 **IndexedDB**，设置用 localStorage | 存档结构化且体积大；设置轻量且需同步读取 | 需处理迁移与配额 |
| ADR-005 | `runtime/` **整体忽略**，规范文档化在 `doc/13` | 保证仓库干净，同时让约定可被新克隆读到 | 新克隆无该目录，需自行创建 |

## 十、开发命令（工程初始化后生效）

```bash
pnpm install          # 安装依赖
pnpm dev              # 启动开发服务器
pnpm build            # 生产构建
pnpm preview          # 预览构建产物
pnpm validate         # 校验配置表（规则在 src/core/validate.js，本地入口 runtime/tools/validate.js）
pnpm assets           # 重建素材并校验（scripts/build-assets.mjs）
pnpm assets:check     # 只校验素材、不重新生成（CI 用）
```

> 当前仓库**尚未初始化工程**（无 `package.json`），上述 pnpm 命令在阶段 M0 落地后生效。在此之前素材生产线**可直接用 node 运行**（零第三方依赖）：`node scripts/build-assets.mjs`（重建 + 校验）、`node scripts/build-assets.mjs --check`（只校验）。见 [15-开发路线图与里程碑](15-开发路线图与里程碑.md)。

## 十一、Git 协作约定

| 项 | 约定 |
|---|---|
| 分支 | `main` 稳定可玩；`feat/*`、`fix/*`、`docs/*`、`content/*` |
| 提交信息 | `<type>(<scope>): <subject>`，type ∈ `feat`/`fix`/`docs`/`content`/`refactor`/`chore`/`balance` |
| 示例 | `content(quests): 补全第三章 8 条主线` / `docs(world): 登记青丘妖盟 NPC` |
| 提交范围 | 一次提交只做一件事；文档与代码改动尽量分开 |
| 禁止提交 | `runtime/`、`node_modules/`、`dist/`、`.env*`、大于 5MB 的原始素材（放外部图床/仓库并在文档登记） |
| 设计变更 | **先改 `doc/`，再改代码**；PR 描述引用对应文档章节 |
| 素材 | 二进制素材入库前先压缩（瓦片集 ≤ 512KB，精灵图 ≤ 1MB） |

## 十二、部署

| 项 | 方案 |
|---|---|
| 目标 | Vercel 或 GitHub Pages（纯静态） |
| 构建产物 | `dist/` |
| 路径 | GitHub Pages 需设 `base`；Vercel 默认 |
| PWA | `vite-plugin-pwa`，`registerType: 'autoUpdate'`，缓存 `data/*.json` 与 `assets/**` |
| 存档 | 全部在浏览器本地；**不提供云同步**（单机离线定位） |
| 版本提示 | 检测到新版本时提示"重载以更新"，避免旧 Service Worker 卡住 |
| 资产体积门禁 | 单文件上限（瓦片集 ≤ 512 KB、精灵 ≤ 1 MB、音频 ≤ 2 MB；**数值真源见 [14-美术与音频规范](14-美术与音频规范.md) §3.3、§6.4 与 §10.5**）由 `node scripts/check-assets.mjs`（聚合入口 `node scripts/build-assets.mjs --check`）在构建前逐项拦下，超限即视为构建失败 |
