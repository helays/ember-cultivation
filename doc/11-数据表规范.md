# 11 · 数据表规范

> **本文档是全项目 ID 与字段的唯一真源。** 任何文档、配置表、代码中出现的 ID 与字段名，必须能在此处查到；查不到就是错误。
> 冲突处理：与 [01-世界观与设定](01-世界观与设定.md) 冲突时，**命名以本文档为准**，设定以 01 为准。
>
> 相关文档：[02-核心玩法系统](02-核心玩法系统.md) · [13-技术架构与工程约定](13-技术架构与工程约定.md)

## 一、总则

1. **一切 ID 为 ASCII 小写 kebab-case**，形如 `前缀-单词-单词`，禁止中文、下划线、驼峰、大写。
2. **ID 一经发布不改名**，只能弃用并新建（避免存档与引用失效）。
3. 所有配置表为 JSON，编码 `UTF-8`，缩进 2 空格，键名 `camelCase`。
4. 表中所有内容**面向数据**：代码只读表，不得硬编码物品/敌人/任务。
5. 每张表顶部有 `$schema` 与 `version` 字段，便于迁移。
6. **"配置"的范畴不限于 `src/data/*.json`**：以下几份文件同样是**面向数据的唯一真源**，与配置表同级受本规范约束（只读、不得在代码或其它文档里复述其内容）——
   - `src/assets/palette.json`：主调色板（16 色固定索引板，见 §5.9 的 `palette` 字段）；
   - `src/assets/assets.manifest.json`：素材清单与素材状态（字段结构见 §5.9）；
   - `src/assets/pixel/**/*.px.txt`、`.atlas.json`：像素矩阵与图集源（字段结构见 §5.10）；
   - `src/assets/psg/**/*.psg.txt`：PSG 音序源（字段结构见 §5.11）。
   上述文件均带 `version` 字段（`$schema` 可选），版本号变更同样按 §1 第 2 条处理：**只增不改名**。

## 三、通用字段约定

### 3.1 稀有度

| 值 | 名称 | 颜色 | 说明 |
|---|---|---|---|
| `common` | 凡品 | 灰白 | 常用消耗品 |
| `fine` | 良品 | 绿 | 有用但常见 |
| `rare` | 珍品 | 蓝 | 支线稀有奖励 |
| `epic` | 灵品 | 紫 | 支线传说奖励、Boss 掉落 |

## 四、任务表（`quests.json`）

任务表是内容主体，**本条结构适用于 `mq-` / `sq-` / `dq-` / `rq-` / `eq-` 全部任务**。

```json
{
  "id": "sq-qy-01",
  "name": "夜遇僵尸",
  "type": "side",
  "level": "common",
  "chapter": 1,
  "giver": "npc-zhao-bu",
  "prereq": ["mq-1-02"],
  "repeatable": false,
  "conflicts": [],
  "trigger": {
    "mode": "interact",
    "map": "map-qingyun",
    "timeOfDay": ["night"],
    "conditions": [
      { "type": "flag", "key": "flag-zombie-raid", "value": true },
      { "type": "realm", "min": 1 }
    ],
    "chance": 1.0,

  "summary": "赵捕头说镇外又出现了夜行的东西。",
  "steps": [
    { "no": 1, "desc": "前往乱葬岗外围", "hint": "从青云镇北门出，沿路牌走", "map": "map-luanzang" },

```

### 4.1.1 `trigger` 扩展字段（周期与随机内容）

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `mode` | string | 全部 | `auto` 自动 / `interact` 交互键 / `step` 踩踏 / `distance` 遇敌 / `board` 告示板接取 |
| `map` | `map-*` | 全部 | 触发地图 |
| `timeOfDay` | array | 全部 | `day` / `night` |
| `season` | array | 季节内容 | `spring` / `summer` / `autumn` / `winter` |
| `weather` | array | 可选 | 天气值（见 [10-地图与区域规划](10-地图与区域规划.md) §4.2） |
| `conditions` | array | 全部 | §3.3 白名单 |
| `flags` | object | 可选 | 前置世界标记 |
| `chance` | number | 随机内容 | `0~1` 触发概率；为 `1` 时不掷骰 |
| `once` | bool | 全部 | 只触发一次 |
| `cooldown` | number | 可重复内容 | 冷却游戏日数，落盘为 `flag-num-cd-*` |
| `weight` | number | 随机池 | 池内权重（普通 60 / 稀有 30 / 传说 10 三档基准） |
| `pool` | string | 随机池 | 所属权重池 ID |
| `priority` | number | 全部 | 多个事件同时满足条件时取高者 |

> 扩展字段的使用方式由 [05-日常与随机事件](05-日常与随机事件.md) §八 定义。所有字段必须要么来自静态配置、要么落盘到存档，不得只存在于运行时内存。

### 4.2 字段必填性

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` `name` `type` `chapter` | ✅ | `type` ∈ `main`/`side`/`daily`/`random`/`season` |
| `level` | 支线必填 | 稀有度分级，决定奖励档位 |
| `giver` | 非随机事件必填 | `npc-*` |
| `prereq` | ✅（可为 `[]`） | 前置任务 ID 数组 |
| `repeatable` | ✅ | 日常/悬赏为 `true` |
| `conflicts` | 可选 | 互斥任务 ID（道侣线使用） |
| `trigger` | ✅ | 随机事件可只用 `chance` + `map` |
| `steps` | ✅ | ≥1 步 |
| `battles` | 有战斗时必填 | `at` 指向 `steps[].no` |
| `branches` | 可选 | 有选择时必填 |
| `rewards` | ✅（可为空对象） | — |
| `flags` | ✅（可为 `[]`） | **必须与 `branches`/`effects` 中写入的 flag 一致** |
| `fail` `timeLimit` | ✅（可为 `null`） | 无失败条件时 `null` |
| `related` | ✅ | 交叉引用，用于校验 |

### 4.3 任务设计硬性约束

1. 每条任务**必须至少有一个可见奖励**（修为或物品或声望），不允许"白跑"。
2. 凡写入 `flag-*` 的任务，必须在 `flags` 字段登记。
3. 凡引用的 `item-*` / `enemy-*` / `npc-*` / `map-*` 必须存在于对应表。
4. 主线任务的 `prereq` 必须形成**无环有向图**，且可从未完成任务到达。
5. 支线的 `level` 与奖励档位必须对应：`common` 小奖 / `rare` 中奖 / `epic`+`legend` 大奖且有前置。

## 五、实体表与素材源文件结构（字段速查）

```json
{ "id": "item-dan-zhuji", "name": "筑基丹", "category": "dan", "level": "rare",
```

必填：`id` `name` `category` `level` `desc` `price`。

### 5.2 `enemies.json`

```json
{ "id": "enemy-zombie", "name": "夜行僵尸", "kind": "zombie", "level": "common",
  "stats": { "hp": 60, "mp": 0, "atk": 12, "def": 8, "spd": 6 },
  "ai": "attacker", "affixPool": ["affix-blood", "affix-iron"],
  "weakness": ["fire", "wood"], "resist": ["water"],
  "skills": ["skill-claw"], "drops": [{ "item": "item-mat-shixiong", "chance": 0.4, "qty": [1, 2] }],
  "codex": "yaoguai", "expReward": 40, "stoneReward": [8, 15] }
```

`kind` ∈ `zombie`/`ghost`/`yao`/`beast`/`human`/`spirit`/`boss`；`ai` ∈ `attacker`/`defender`/`support`/`random`/`boss`/`inner-demon`。

**扩展字段**（语义由 [07-敌人与战斗设计](07-敌人与战斗设计.md) 定义）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `baselineRow` | string | 指向「境界 × 分级」属性基线表的行，用于校验该敌人数值是否落在基线区间 |
| `rules.form` | string | 特殊战斗形态（心魔镜像 / 天劫 / 撑过 N 回合等），取值见 [07](07-敌人与战斗设计.md) |
| `encounterTable` | string | 遭遇表 ID，供地图 `encounter` 对象层引用 |

| `alchemy.json` | `id`/`result`/`materials`/`baseRate`/`realmReq`/`timeCost` |
| `crafting.json` | `id`/`result`/`materials`/`qualityRange`/`realmReq` |
| `farming.json` | `seed`/`crop`/`seasons`/`growHours`/`yield` |
| `homestead.json` | `field`/`level`/`cost`/`effect` |
| `codex.json` | `category`/`entries`/`tierBonus`（25/50/100%） |
| `affixes.json` | `id`/`name`/`statMul`/`dropBonus`/`appliesTo` |

### 5.9 `assets.manifest.json`（素材清单）

> 素材的**唯一定义处**：任何 PNG / TSX / 音频若要落到 `src/assets/` 或 `public/`，必须在本清单登记一条；清单与磁盘必须**双向一致**——磁盘无孤儿素材，清单中非 `planned` 的条目无缺失文件。

```json
{ "id": "tileset-town-ground",
  "path": "src/assets/tilesets/town/tileset-town-ground.png",
  "kind": "tile",
  "spec": { "width": 128, "height": 128, "cell": 32, "columns": 4, "rows": 4 },
  "source": "L0", "generator": "scripts/gen-tiles.mjs",
  "status": "placeholder", "license": "project",
  "author": "EmberCultivation contributors",
  "tags": ["town", "ground", "flagstone"] }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `version` | number | ✅ | 清单结构版本（顶层字段） |
| `palette` | string | ✅ | 主调色板真源的路径（顶层字段，指向 `src/assets/palette.json`） |
| `sourceRoots` | object | ✅ | 源文件根目录（顶层字段）：`pixel` 为 `.px.txt` 根，`psg` 为 `.psg.txt` 根 |
| `assets[]` | array | ✅ | 素材条目数组（顶层字段）；以下为条目内字段 |
| `id` | string | ✅ | 素材 ID，全局唯一，取**文件名主干**；前缀规则见 §2 与 [14-美术与音频规范](14-美术与音频规范.md) §5.2 |
| `path` | string | ✅ | 相对仓库根的入库路径；**不得**指向 `runtime/` |
| `kind` | enum | ✅ | `tile` / `sprite` / `portrait` / `ui` / `icon` / `vfx` / `particle` / `bg` / `bgm` / `sfx` |
| `spec` | object | ✅ | 尺寸与播放规格，字段见 §5.9.1 |
| `source` | enum | ✅ | 生产线层级 `L0`~`L4`；五级来源、手段、授权，以及各级使用的清单字段见 [14-美术与音频规范](14-美术与音频规范.md) §4.1（本节不复述） |
| `generator` | string | 由脚本产出时必填 | 产出该素材的脚本路径（如 `scripts/gen-tiles.mjs`） |
| `sourceFile` | string | 由源文件产出时必填 | `.px.txt` / `.psg.txt` 源文件路径 |
| `atlas` | string | 多帧出图时必填 | `.atlas.json` 图集定义路径（见 §5.10） |
| `status` | enum | ✅ | `planned` 已声明未产出 / `placeholder` 可玩占位 / `final` 正式 |
| `license` | string | ✅ | `project`（项目自有）或 SPDX 式标识（`CC0` / `CC-BY-4.0` / `OFL-1.1` 等） |
| `author` | string | ✅ | 作者 / 贡献者署名 |
| `tags` | string[] | 可选 | 检索标签（区域、用途、类别） |

**硬规则**：

1. `status: "planned"` 时**文件允许不存在**（只表示"已声明未产出"）；`placeholder` / `final` 时文件必须存在，否则视为构建失败。
2. `license` 字段的必填性随状态变化：`planned` 条目允许暂缺，一旦进入 `placeholder` / `final` 则不得为空；`license` **非 `project` 时，必须同时登记进 [14-美术与音频规范](14-美术与音频规范.md) 附录 A.1**，登记字段缺一不可。
3. `kind: "tile"` 时**禁止使用调色板索引 0**（保留透明槽）——瓦片必须完全不透明。
4. `id` 与 `path` 一经发布不改名，只能弃用并新建条目（同 §1 第 2 条）。
5. 清单属**严格档**内容：其它文档只允许写"见 `assets.manifest.json`"，不得复述素材清单或素材规格数字（[00-文档索引](00-文档索引.md) §八）。

#### 5.9.1 `spec` 字段

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `width` / `height` | number | 位图 | 目标 PNG 的像素尺寸，必须**精确相等**（不允许近似） |
| `cell` | number | 瓦片集 / 图集 | 单格边长（瓦片尺寸见 [14-美术与音频规范](14-美术与音频规范.md) §6.1） |
| `frameHeight` | number | 帧高与画布高不同的精灵 | 单帧高度（如行走帧） |
| `columns` / `rows` | number | 网格图 / 图集 | 列数与行数 |
| `fps` | number | 动画 | 播放帧率 |
| `nineSlice` | number | UI 九宫格 | 边角切片宽度 |
| `loop` | bool | BGM | 是否无缝循环 |
| `durationTarget` | number | BGM | 目标时长（秒） |
| `maxMs` | number | SFX | 时长上限（毫秒） |

### 5.10 `.px.txt` 像素矩阵（L1 美术源文件）

> 存放于 `sourceRoots.pixel`。**格式的唯一定义处是 `scripts/lib/pixels.mjs` 的文件头注释**（来源分级、生成命令与落点见 [14-美术与音频规范](14-美术与音频规范.md) §4.1）；本节只登记字段与取值约束。解析的唯一实现是 `scripts/lib/pixels.mjs`，出图的唯一实现是 `scripts/render-pixels.mjs`（[13-技术架构与工程约定](13-技术架构与工程约定.md) §7.1）。

**头字段**（每行 `@键 值`，`#` 起头为注释，`---` 为头字段区与正文的分隔行）：

| 头字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `@id` | ✅ | 素材 ID | 必须与 `assets.manifest.json` 的 `id` 一致（[14-美术与音频规范](14-美术与音频规范.md) §5.2） |
| `@kind` | 由源文件产出时必填 | `tile` / `sprite` / `ui` / `icon` / `vfx` / `particle` / `portrait` / `bg` | 取值同 §5.9；**`kind: tile` 的矩阵必须显式声明**，否则"瓦片禁用透明槽"的校验无法生效（图集的 `kind` 写在 `.atlas.json` 里） |
| `@size` | ✅ | `宽x高`（如 `32x48`） | 正文的行宽与行数必须**精确等于**该值 |
| `@anchor` | 可选 | `x,y` | 锚点像素坐标：**内容包围盒的底边中心**；同一动作各帧必须像素级一致（[14-美术与音频规范](14-美术与音频规范.md) §7.2） |
| `@out` | 单图必填 | 相对仓库根的输出路径 | 必须等于清单的 `path`；被 `.atlas.json` 引用的帧不写 |
| `@tags` | 可选 | 空白分隔的标签 | 与清单 `tags` 对应 |
| `---` | ✅ | 三个及以上 `-` | 分隔行；缺失即解析失败 |

**像素字符集**（16 个符号，一一对应调色板索引；调色板真源见 [`src/assets/palette.json`](../src/assets/palette.json)）：

| 字符 | `.` | `1`~`9` | `a`~`f` |
|---|---|---|---|
| 索引 | 0（保留透明槽） | 1~9 | 10~15 |

**硬规则**：每行字符数 = `@size` 的宽，行数 = `@size` 的高；字符必须在上述字符集内；`kind: tile`（含图集的 `kind` 为 `tile`）时**禁止出现 `.`**。

**多帧图集 `.atlas.json`**（与帧矩阵同目录）：声明帧序，由 `scripts/render-pixels.mjs` 自动拼成网格图集 PNG-8；字段、命名与运行时取帧方式见 [14-美术与音频规范](14-美术与音频规范.md) §5.2、§7.2。被引用的帧矩阵不再单独出图。

### 5.11 `.psg.txt` PSG 音序（L2 音频源文件）

> 存放于 `sourceRoots.psg`。**格式、通道模型与示例的唯一定义处是 [14-美术与音频规范](14-美术与音频规范.md) §10.1**，本节只登记要素与取值域；头字段区与音序正文以 `---` 分隔，`#` 起头为注释。

| 要素 | 取值域 | 说明 |
|---|---|---|
| 元数据 | `@id` / `@out` / `@tempo` / `@loop` / `@tuning` | 首部、`---` 之前；`@out` 必须等于清单的 `path` |
| 通道 | `CH1`~`CH4` | 方波主旋律 / 方波和声与对位 / 三角波低音 / 噪声打击（对齐卡带机四通道硬件） |
| 通道参数行 | `w=`（占空比，仅方波）/ `env=`（起振、衰减、保持、释放四段毫秒）/ `noise=`（仅 `CH4`，取值 `white` / `metal`） | 每通道一行 |
| 音符行 | `{通道} {音名或 -} {时值} {音量} {效果}` | 音名如 `C4` / `D#5`；**休止写 `-`**；时值用分数（`1/4`、`1/8.` 附点） |
| 音量 | `v=0`~`15` | 与卡带机 4 位音量域一致 |
| 效果 | `slide=` 滑音 / `arp=` 琶音 / `vib=` 颤音 / `retrig` 重触发 | 可省略 |
| 循环 | `@loop` 的循环长度（合成时取整到整数小节） | BGM 必须无缝循环（[14-美术与音频规范](14-美术与音频规范.md) §10.4） |

## 六、世界标记登记规则

1. `flag-*` 必须注册在**世界标记登记表**中，登记项包含：ID、类型（布尔/数值）、写入任务、读取任务、语义。**全局登记表 = 以下三份附录的并集**，任何新增标记必须落在其中之一：
   - [03-主线任务](03-主线任务.md) 附录 A —— 主线标记
   - [04-支线任务](04-支线任务.md) 附录 A —— 支线标记（含道侣线与同伴线）
   - [05-日常与随机事件](05-日常与随机事件.md) 附录 A —— 每日 / 季节 / 月圆 / 随机 / 宗门周期标记
   校验脚本按这三份附录的并集核对，未登记的 `flag-*` 视为配置错误。
2. 布尔标记只允许 `true`（存在即真），避免 `false` 与"未设置"混淆。数值标记命名以 `flag-num-` 开头。
3. 标记不得删除，只能废弃（标注 `[废弃]`）。
4. 命名语义化，禁止 `flag-1`、`flag-tmp` 这类无意义 ID。

## 七、校验清单（配置表与素材自检）

新增或修改配置后，逐项检查。

**配置表侧**（规则实现：`src/core/validate.js`；本地独立运行入口：`runtime/tools/validate.js`；产物放 `runtime/reports/`，均不入库）：

- [ ] 所有 `id` 匹配 §2 前缀规则，且全局唯一
- [ ] 所有跨表引用（`item-*` / `enemy-*` / `npc-*` / `map-*` / `skill-*`）可解析
- [ ] 所有 `effects[].type` 与 `conditions[].type` 在 §3.2 / §3.3 白名单内
- [ ] 所有任务 `flags` 与 `branches` 中实际写入的 flag 一致
- [ ] 任务 `prereq` 图无环
- [ ] 支线 `level` 与奖励档位匹配
- [ ] 所有 `flag-*` 已在登记表中注册
- [ ] 无孤立任务（除首任务外，每条任务至少是一个任务的前置或被引用）
- [ ] JSON 可解析、无重复键
- [ ] 玩家数值在 [16-数值设计](16-数值设计.md) §4.2 的属性表内；敌人数值在 [16-数值设计](16-数值设计.md) §7.3 的基线区间内

**素材侧**（唯一入口：`node scripts/check-assets.mjs`；聚合入口 `node scripts/build-assets.mjs --check` 会先跑各生成器的 `--check`（不写盘）、最后调用本校验器；生产线脚本见 [13-技术架构与工程约定](13-技术架构与工程约定.md) §7.1。**逐条编号与判定细节的唯一真源是 [14-美术与音频规范](14-美术与音频规范.md) 附录 A.3**）：

- [ ] **调色板一致**：`src/assets/palette.json`、`src/core/constants.js` 的 `PALETTE`、[14-美术与音频规范](14-美术与音频规范.md) §2.1 的色板表三者逐条一致（无手改痕迹）

- [ ] **音频规格**：采样率 / 声道 / 时长 / 体积在上限内（[14-美术与音频规范](14-美术与音频规范.md) §10.5）
