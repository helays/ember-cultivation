# 11 · 数据表规范

> **本文档是全项目 ID 与字段的唯一真源。** 任何文档、配置表、代码中出现的 ID 与字段名，必须能在此处查到；查不到就是错误。
> 冲突处理：与 [01-世界观与设定](01-世界观与设定.md) 冲突时，**命名以本文档为准**，设定以 01 为准。
>
> 相关文档：[02-核心玩法系统](02-核心玩法系统.md) · [13-技术架构与工程约定](13-技术架构与工程约定.md)

## 一、总则

1. **一切 ID 为 ASCII 小写 kebab-case**，形如 `前缀-单词-单词`，禁止中文、下划线、驼峰、大写。
2. **ID 一经发布不改名**，只能弃用并新建（避免存档与引用失效）。
3. 所有配置表为 JSON，编码 `UTF-8`，缩进 2 空格，键名 `camelCase`。
4. 表中所有内容**面向数据**：代码只读表，不得硬编码物品/敌人/任务。
5. 每张表顶部有 `$schema` 与 `version` 字段，便于迁移。

## 三、通用字段约定

### 3.1 稀有度

| 值 | 名称 | 颜色 | 说明 |
|---|---|---|---|
| `common` | 凡品 | 灰白 | 常用消耗品 |
| `fine` | 良品 | 绿 | 有用但常见 |
| `rare` | 珍品 | 蓝 | 支线稀有奖励 |
| `epic` | 灵品 | 紫 | 支线传说奖励、Boss 掉落 |
| `legend` | 神品 | 金 | 唯一，全流程 1~2 件 |
| `myth` | 仙品 | 赤 | 仅结局/多周目 |

### 3.2 效果（`effects`）白名单

| `type` | 参数 | 说明 |
|---|---|---|

| `consume` | `item`, `qty` | 消耗物品 |
| `flag` | `key`, `value` | 写入世界标记 |
| `faction` | `faction`, `value` | 势力声望增减 |
| `favor` | `npc`, `value` | NPC 好感增减 |
| `battle` | `enemy`/`boss`, `count`, `level?`, `rules?` | 触发战斗，`rules` 可写胜负条件 |
| `move` | `map`, `spawn` | 传送 |
| `dialog` | `npc`, `node` | 播放对话节点 |
| `unlockMap` | `map` | 解锁地图 |
| `unlockSkill` | `skill` | 学会技能 |
| `unlockGongfa` | `gongfa` | 学会功法 |
| `unlockCodex` | `category`, `id` | 解锁图鉴条目 |
| `quest` | `quest`, `state` | 修改任务状态 |
| `time` | `hours` | 推进时辰 |
| `hp` / `mp` / `mind` | `value` | 直接增减资源 |

### 3.3 条件（`conditions`）白名单

| `type` | 参数 | 说明 |
|---|---|---|

| `questState` | `quest`, `state` | 任务状态检查 |

| `faction` | `faction`, `min` | 声望下限 |

`locked` → `available` → `active` → `completed` / `failed` / `abandoned`

## 四、任务表（`quests.json`）

任务表是内容主体，**本条结构适用于 `mq-` / `sq-` / `dq-` / `rq-` / `eq-` 全部任务**。

```json
{
  "id": "sq-qy-01",
  "name": "夜遇僵尸",
  "type": "side",
  "level": "common",
  "chapter": 1,
  "giver": "npc-zhao-bu",
  "prereq": ["mq-1-02"],
  "repeatable": false,
  "conflicts": [],
  "trigger": {
    "mode": "interact",
    "map": "map-qingyun",
    "timeOfDay": ["night"],
    "conditions": [
      { "type": "flag", "key": "flag-zombie-raid", "value": true },
      { "type": "realm", "min": 1 }
    ],
    "chance": 1.0,
    "once": true
  },
  "summary": "赵捕头说镇外又出现了夜行的东西。",
  "steps": [
    { "no": 1, "desc": "前往乱葬岗外围", "hint": "从青云镇北门出，沿路牌走", "map": "map-luanzang" },
    { "no": 2, "desc": "击败夜行僵尸", "battle": "enemy-zombie" },
    { "no": 3, "desc": "回报赵捕头", "hint": "青云镇衙门", "map": "map-qingyun" }

                      { "type": "flag", "key": "flag-zombie-freed", "value": true },
                      { "type": "faction", "faction": "fac-maoshan", "value": 5 }] }

    "favor": { "npc-zhao-bu": 5 },
    "codex": [{ "category": "yaoguai", "id": "enemy-zombie" }]

  "fail": { "conditions": [], "onFail": "abandoned" },
  "timeLimit": null,
  "related": { "npcs": ["npc-zhao-bu"], "enemies": ["enemy-zombie"], "maps": ["map-luanzang"] }

```

### 4.1.1 `trigger` 扩展字段（周期与随机内容）

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `mode` | string | 全部 | `auto` 自动 / `interact` 交互键 / `step` 踩踏 / `distance` 遇敌 / `board` 告示板接取 |
| `map` | `map-*` | 全部 | 触发地图 |
| `timeOfDay` | array | 全部 | `day` / `night` |
| `season` | array | 季节内容 | `spring` / `summer` / `autumn` / `winter` |
| `weather` | array | 可选 | 天气值（见 [10-地图与区域规划](10-地图与区域规划.md) §4.2） |
| `conditions` | array | 全部 | §3.3 白名单 |
| `flags` | object | 可选 | 前置世界标记 |
| `chance` | number | 随机内容 | `0~1` 触发概率；为 `1` 时不掷骰 |
| `once` | bool | 全部 | 只触发一次 |
| `cooldown` | number | 可重复内容 | 冷却游戏日数，落盘为 `flag-num-cd-*` |
| `weight` | number | 随机池 | 池内权重（普通 60 / 稀有 30 / 传说 10 三档基准） |
| `pool` | string | 随机池 | 所属权重池 ID |
| `priority` | number | 全部 | 多个事件同时满足条件时取高者 |

> 扩展字段的使用方式由 [05-日常与随机事件](05-日常与随机事件.md) §八 定义。所有字段必须要么来自静态配置、要么落盘到存档，不得只存在于运行时内存。

### 4.2 字段必填性

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` `name` `type` `chapter` | ✅ | `type` ∈ `main`/`side`/`daily`/`random`/`season` |
| `level` | 支线必填 | 稀有度分级，决定奖励档位 |
| `giver` | 非随机事件必填 | `npc-*` |
| `prereq` | ✅（可为 `[]`） | 前置任务 ID 数组 |
| `repeatable` | ✅ | 日常/悬赏为 `true` |
| `conflicts` | 可选 | 互斥任务 ID（道侣线使用） |
| `trigger` | ✅ | 随机事件可只用 `chance` + `map` |
| `steps` | ✅ | ≥1 步 |
| `battles` | 有战斗时必填 | `at` 指向 `steps[].no` |
| `branches` | 可选 | 有选择时必填 |
| `rewards` | ✅（可为空对象） | — |
| `flags` | ✅（可为 `[]`） | **必须与 `branches`/`effects` 中写入的 flag 一致** |
| `fail` `timeLimit` | ✅（可为 `null`） | 无失败条件时 `null` |
| `related` | ✅ | 交叉引用，用于校验 |

### 4.3 任务设计硬性约束

1. 每条任务**必须至少有一个可见奖励**（修为或物品或声望），不允许"白跑"。
2. 凡写入 `flag-*` 的任务，必须在 `flags` 字段登记。
3. 凡引用的 `item-*` / `enemy-*` / `npc-*` / `map-*` 必须存在于对应表。
4. 主线任务的 `prereq` 必须形成**无环有向图**，且可从未完成任务到达。
5. 支线的 `level` 与奖励档位必须对应：`common` 小奖 / `rare` 中奖 / `epic`+`legend` 大奖且有前置。

## 五、实体表结构（字段速查）

### 5.1 `items.json`

```json
{ "id": "item-dan-zhuji", "name": "筑基丹", "category": "dan", "level": "rare",
  "desc": "服下可增三成筑基把握。", "stack": 99, "price": 800, "sellable": true,
  "usable": { "inBattle": false, "inField": true },
  "effects": [{ "type": "flag", "key": "flag-zhuji-boost", "value": true }] }
```

必填：`id` `name` `category` `level` `desc` `price`。

### 5.2 `enemies.json`

```json
{ "id": "enemy-zombie", "name": "夜行僵尸", "kind": "zombie", "level": "common",
  "stats": { "hp": 60, "mp": 0, "atk": 12, "def": 8, "spd": 6 },
  "ai": "attacker", "affixPool": ["affix-blood", "affix-iron"],
  "weakness": ["fire", "wood"], "resist": ["water"],
  "skills": ["skill-claw"], "drops": [{ "item": "item-mat-shixiong", "chance": 0.4, "qty": [1, 2] }],
  "codex": "yaoguai", "expReward": 40, "stoneReward": [8, 15] }
```

`kind` ∈ `zombie`/`ghost`/`yao`/`beast`/`human`/`spirit`/`boss`；`ai` ∈ `attacker`/`defender`/`support`/`random`/`boss`/`inner-demon`。

**扩展字段**（语义由 [07-敌人与战斗设计](07-敌人与战斗设计.md) 定义）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `baselineRow` | string | 指向「境界 × 分级」属性基线表的行，用于校验该敌人数值是否落在基线区间 |
| `rules.form` | string | 特殊战斗形态（心魔镜像 / 天劫 / 撑过 N 回合等），取值见 [07](07-敌人与战斗设计.md) |
| `encounterTable` | string | 遭遇表 ID，供地图 `encounter` 对象层引用 |

  "upgradeCost": [1, 2, 4, 8], "req": { "realm": 1, "gongfa": ["gongfa-kunlun-zhengfa"] } }

`type` ∈ `damage`/`aoe`/`buff`/`debuff`/`heal`/`summon`；`target` ∈ `self`/`single`/`all-enemy`/`all-ally`。

## 六、世界标记登记规则

1. `flag-*` 必须注册在**世界标记登记表**中，登记项包含：ID、类型（布尔/数值）、写入任务、读取任务、语义。**全局登记表 = 以下三份附录的并集**，任何新增标记必须落在其中之一：
   - [03-主线任务](03-主线任务.md) 附录 A —— 主线标记
   - [04-支线任务](04-支线任务.md) 附录 A —— 支线标记（含道侣线与同伴线）
   - [05-日常与随机事件](05-日常与随机事件.md) 附录 A —— 每日 / 季节 / 月圆 / 随机 / 宗门周期标记
   校验脚本按这三份附录的并集核对，未登记的 `flag-*` 视为配置错误。
2. 布尔标记只允许 `true`（存在即真），避免 `false` 与"未设置"混淆。数值标记命名以 `flag-num-` 开头。
3. 标记不得删除，只能废弃（标注 `[废弃]`）。
4. 命名语义化，禁止 `flag-1`、`flag-tmp` 这类无意义 ID。

## 七、校验清单（配置表自检）

新增或修改配置后，逐项检查（校验脚本放 `runtime/tools/`，产物放 `runtime/reports/`，均不入库）：

- [ ] 所有 `id` 匹配 §2 前缀规则，且全局唯一
- [ ] 所有跨表引用（`item-*` / `enemy-*` / `npc-*` / `map-*` / `skill-*`）可解析
- [ ] 所有 `effects[].type` 与 `conditions[].type` 在 §3.2 / §3.3 白名单内
- [ ] 所有任务 `flags` 与 `branches` 中实际写入的 flag 一致
- [ ] 任务 `prereq` 图无环
- [ ] 支线 `level` 与奖励档位匹配
- [ ] 所有 `flag-*` 已在登记表中注册
- [ ] 无孤立任务（除首任务外，每条任务至少是一个任务的前置或被引用）
- [ ] JSON 可解析、无重复键
- [ ] 玩家数值在 [16-数值设计](16-数值设计.md) §4.2 的属性表内；敌人数值在 [16-数值设计](16-数值设计.md) §7.3 的基线区间内
